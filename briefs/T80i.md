# T80i security review (crates/silicon): trust-boundary code, findings proven by tests
Worker: hydrogen-high (agy). Budget: one run, at most 90 minutes. First read `briefs/_RULES.md`, then only the src files named below.
**May touch:** new `crates/silicon/tests/security.rs`; `crates/silicon/src/` only for the smallest fix of a defect that a test in security.rs reproduces. No other crate, no new dependencies.

## Focus (read these, think like an attacker sending the input)
`src/` the decoder on arbitrary instruction words, MMU page walks with hostile page tables (loops, out-of-range physical addresses, misaligned superpages), device MMIO at hostile addresses and sizes, the H extension two-stage walk. A guest must never panic or hang the host.

## Rules
- Every finding is a test in `tests/security.rs` that failed before your fix (panic, hang over 1 s, allocation over 64 MiB, wrong accept, path escape, or wrong output) and passes after it. Name the test after the defect.
- No finding without a test. If you find nothing, security.rs still holds at least 8 attack tests (malformed, oversized, truncated, hostile values) that pass, and the report says `none found`.
- Do not weaken existing tests or limits. Keep public APIs unchanged.

## Report
`reports/T80i.md` (at most 15 lines): files read, each finding (test name, file:line of the fix, one line why), test count, gate last line.

## Extra check the leader will run
Each fix re-read and each test reverted against the old src to confirm it fails there; `bash tools/check.sh silicon`; workspace gate.

# T86g tool (crates/odyssey): the `odyssey` command-line tool
Worker: hydrogen-high (agy). Budget: one run, at most 90 minutes. First read `briefs/_RULES.md`, then `docs/APPS.md`
(the "Tool conventions" section and the `odyssey` row; those rules are part of this brief), then only the public
items of `crates/odyssey/src/lib.rs` and the modules they point to that you call. Read nothing else.
**May touch:** `crates/odyssey/src/bin/odyssey.rs`, `crates/odyssey/tests/cli_odyssey.rs`, `crates/odyssey/Cargo.toml`
(a `[[bin]]` entry or a path dependency already in the workspace, never one that creates a cycle) only. Do not
change library code; if a subcommand needs something the library does not offer, leave it out and say so. Zero
external crates. Your gate is `bash tools/check.sh odyssey`; you can only run commands for `odyssey`.

## Tool
- `odyssey`: `tokens FILE.html` (one token per line), `tree FILE.html` (indented DOM tree), `select SEL FILE.html` (matching elements, one per line with their path), `render FILE.html --width N --out PAGE.png` only if the crate has a renderer to pixels (else leave it out and say so; pigment may be a dependency for PNG encoding).

## Tests
`tests/cli_odyssey.rs` as `docs/APPS.md` says: `--help`, `--version`, every subcommand on a good input, one bad input
each (exit 1 and a `odyssey:` message), an unknown subcommand (exit 2). Run `cargo fmt -p odyssey` before the gate.

## Report
`reports/T86g.md` (at most 10 lines): subcommands, anything left out and why, tests, gate last line.

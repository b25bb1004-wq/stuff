# T86b tools (crates/argo, crates/chronos, crates/calliope, crates/kairos, crates/midas): five command-line tools
Worker: hydrogen-high (agy). Budget: one run, at most 150 minutes. First read `briefs/_RULES.md`, then
`docs/APPS.md` (the "Tool conventions" section and the table rows for these five; the rules there are part of this
brief), then for each crate only the public items of its `src/lib.rs` and the modules those items point to that you
call. Read nothing else.
**May touch:** in each of the five crates only `src/bin/<id>.rs`, `tests/cli.rs` and `Cargo.toml` (a `[[bin]]`
entry if needed, dev-deps already in the workspace). Do not change library code; if a tool needs something the
library does not offer, leave that subcommand out and say so. Zero external crates.

## Tools
- `argo`: `solve INDEX MANIFEST` (prints `name version` lines or the conflict explanation, exit 1),
  `lock INDEX MANIFEST -o LOCK`, `install LOCK STORE_DIR` (through the library's install with packages read from a
  local directory given by `--from DIR`), `serve INDEX_DIR [--listen 127.0.0.1:7500]` using the library registry if
  it has a server; else leave `serve` out (deploy's `argo-registry` covers it) and say so. Formats are the
  library's own text formats.
- `chronos`: a git-like tool on a directory: `init [DIR]`, `add PATH...`, `commit -m MSG`, `log`,
  `branch [NAME]`, `checkout NAME`, `cat-file ID`, `status`. Repository data under `DIR/.chronos/`. Object ids are
  SHA-256 hex as the library computes them; test that the id of a known blob matches the library's own function.
- `calliope`: `grep REGEX FILE...` (`file:line:col: text`, exit 1 when no match, 2 on a bad regex),
  `edit SCRIPT FILE` where SCRIPT lines are `goto LINE COL`, `insert TEXT`, `delete N`, `undo`, `redo`, `cursor
  add LINE COL`, `save`; prints the buffer at the end (or writes it back on `save`).
- `kairos`: `sim FILE` where FILE has `cpus N` and `task NAME WEIGHT WORK` lines; prints a per-CPU timeline in
  ticks and each task's share against its weight; same input gives the same output.
- `midas`: `sim FILE` with `heap BYTES`, `alloc SIZE`, `free N` lines; after each step the buddy free lists per order
  and bytes in use; a double free or a bad index prints an error and exits 1 (no panic).

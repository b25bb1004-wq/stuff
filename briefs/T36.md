# T36 mercury (crates/mercury): HTTP/1.1 parser and writer, no I/O inside
Worker: hydrogen. First read `briefs/_RULES.md` and `crates/mercury/src/lib.rs`.

**May touch:** `crates/mercury/**` only (its `Cargo.toml` may add `assay` as a dev-dependency by
path, as other crates do). `no_std` + `alloc`, `#![forbid(unsafe_code)]`, zero external crates.

## Why
The server (T37), Chronos push/pull (T45), the package registry (T47) and the browser (T67) all
speak HTTP/1.1 through this code. It must never panic or allocate without bound on hostile input.

## Public API (exact)
```rust
pub struct Limits { pub max_head: usize, pub max_headers: usize, pub max_body: usize }
impl Default for Limits { /* 16 KiB head, 100 headers, 8 MiB body */ }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Error { Incomplete, BadRequestLine, BadStatusLine, BadVersion, BadHeader, HeadTooLarge,
                 TooManyHeaders, BodyTooLarge, BadChunk, BadContentLength, BadMethod }
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Request { pub method: String, pub target: String, pub minor: u8, // HTTP/1.minor, 0 or 1
                     pub headers: Vec<(String, Vec<u8>)>, pub body: Vec<u8> }
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Response { pub minor: u8, pub status: u16, pub reason: String,
                      pub headers: Vec<(String, Vec<u8>)>, pub body: Vec<u8> }
/// Parse one request from the front of `buf`. Ok((request, bytes_used)); Err(Incomplete) when
/// more bytes are needed; any other Err is final for this connection.
pub fn parse_request(buf: &[u8], lim: &Limits) -> Result<(Request, usize), Error>;
/// Same for a response. `head_only` is true for replies to HEAD and for 1xx/204/304 (no body).
pub fn parse_response(buf: &[u8], lim: &Limits, head_only: bool) -> Result<(Response, usize), Error>;
pub fn write_request(r: &Request) -> Vec<u8>;    // Content-Length added when body is non-empty
pub fn write_response(r: &Response) -> Vec<u8>;  // and not already present
impl Request  { pub fn header(&self, name: &str) -> Option<&[u8]>; pub fn keep_alive(&self) -> bool; }
impl Response { pub fn header(&self, name: &str) -> Option<&[u8]>; }
```
## Behaviour (RFC 9112)
- Lines end in CRLF; a bare LF is also accepted. Header names are tokens, matched without
  case by `header()` (first match); stored as received. Values are trimmed of spaces and tabs.
  Obsolete line folding is `BadHeader`.
- Body: `Transfer-Encoding: chunked` (chunk extensions ignored, trailers parsed and dropped) wins
  over `Content-Length`; two different `Content-Length` values or a non-digit one is
  `BadContentLength`; a request with neither has an empty body; a response with neither reads to
  the end of `buf` only when `head_only` is false and the caller has the whole stream, so return
  `Incomplete` in that case (the server never needs it).
- Methods: tokens; unknown methods are allowed. Version other than HTTP/1.0 or 1.1 is `BadVersion`.
- `keep_alive`: 1.1 unless `Connection: close`; 1.0 only with `Connection: keep-alive`.
- Limits are checked before allocating: a head larger than `max_head` is `HeadTooLarge` as soon
  as that many bytes arrive without the blank line; same for the body and chunk sizes.
- Pipelining: `bytes_used` lets the caller parse the next request from the rest of `buf`.
- No panic and no unbounded allocation for any input.

## Tests required
- A corpus of at least 40 requests and 20 responses (valid and invalid, both line endings,
  chunked with extensions and trailers, pipelined pairs) with the exact expected result.
- Every prefix of every valid message gives `Incomplete`; the full message parses.
- Round trip: `parse(write(x)) == x` for generated requests and responses (`forall`, 500 cases).
- Fuzz (`forall`, 2000 cases): random bytes and mutated valid messages never panic and never
  return more `bytes_used` than `buf.len()`.

## Tool
- `zeusctl` (host only: the file starts with `#![cfg(not(target_os = "none"))]` plus a no-op `main` for the
  other case if needed so the riscv build still works): `run [--zeus PATH] [--guest lithium[:MiB]]...
  [--guest titan[:MiB]] [--titan PATH] [--steps N]` boots zeus with the guests (default: one lithium guest, 4 MiB)
  on Silicon via `build_machine`, runs up to N steps (default 20 M), prints the console split per source with
  `split_console` as `[name] line`, then `exit:` and steps. `--zeus` defaults to
  `target/zeus-bin/riscv64gc-unknown-none-elf/release/zeus`, `--titan` to
  `target/titan-kernel/riscv64gc-unknown-none-elf/release/kernel`; a missing file is exit 1 with a message naming
  the exact cargo command that builds it (copy it from `tests/guests.rs`). Bad guest names or sizes exit 2.

## Tests
`tests/cli_zeusctl.rs` as `docs/APPS.md` says: `--help`, `--version` (`zeusctl 0.1.0`), missing zeus file exit 1
with the build command in the message, bad guest spec exit 2, unknown subcommand exit 2, and (only when the zeus
ELF exists, else skip with a printed note) one lithium guest run whose output contains `zeus: lithium exited 0`.
Run `cargo fmt -p zeus` before the gate.

## Report
`reports/T86q.md` (at most 10 lines): what runs, anything left out and why, tests, gate last line.

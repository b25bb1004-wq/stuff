## Public API (exact), `seam::node::net`
```rust
pub type PeerId = u32;
pub const SYNC_INTERVAL_US: u64 = 100_000; // time is microseconds, as in tremor
pub const MAX_MSG: usize = 4 << 20;        // larger stream payloads are dropped
pub struct Peer { /* private */ }
impl Peer {
    pub fn new(id: PeerId, node: Node, secret: [u8; 32], seed: [u8; 32]) -> Peer;
    pub fn public_key(&self) -> [u8; 32];            // tremor X25519 static key from secret
    pub fn add_peer(&mut self, id: PeerId, key: [u8; 32], now: u64);
    pub fn node(&self) -> &Node;
    pub fn inject(&mut self, msg: Msg, now: u64);    // local message, as if received
    pub fn receive(&mut self, from: PeerId, datagram: &[u8], now: u64);
    pub fn poll_transmit(&mut self, now: u64) -> Option<(PeerId, Vec<u8>)>;
    pub fn timeout(&self) -> Option<u64>;            // earliest tremor timer or next sync tick
    pub fn on_timeout(&mut self, now: u64);
    pub fn connected(&self) -> Vec<PeerId>;          // sorted, handshake complete
}
```

## Behaviour (exact)
- Links: for each added peer, the lower id dials (`Connection::connect` with that peer's key and a
  per-link seed derived deterministically from `seed` and the peer id); the higher id accepts on
  its own `tremor::Server` (one per Peer, from `secret`). A datagram from peer X to Y goes to Y's
  client connection for X when Y < X, else to Y's server; remember server cid to PeerId. Datagrams
  from ids never added are dropped. Never panic on any datagram.
- Framing: one `Msg` per tremor stream: open, write `Msg::encode()`, finish. On receive, drain every
  readable stream; a finished stream whose bytes decode is handed to `Node::handle`; bytes that do
  not decode, or exceed `MAX_MSG`, are dropped (reset the stream), never a panic.
- Gossip: every `Msg` that `Node::handle` returns (from `inject` or a received message) is sent to
  every connected peer. Messages produced before a link is connected wait in a per-link queue
  (at most 10_000; oldest dropped) and are sent once it connects.
- Sync: every `SYNC_INTERVAL_US` (first tick at the first `on_timeout` at or after
  `SYNC_INTERVAL_US` past creation), send `Msg::Tip { hash, height }` of the node's tip plus one
  `Msg::GetBlock(h)` for every `h` in `Node::missing()` to every connected peer.
- `on_timeout` drives tremor timers of every connection and the server, then the sync tick.
- Deterministic: the same inputs in the same order give the same datagrams.

## Tests required
`tests/net.rs`: 3 to 5 peers in a simulated network (the test owns the clock and a datagram
queue with seeded loss, delay and reordering): blocks from forked validators injected at random
peers converge on the same tip with the same state root; a peer added late catches up through
sync; hostile datagrams (random bytes, truncated and bit-flipped real datagrams) never panic;
determinism (two runs, same seed, identical tips and datagram counts).

## Extra check the leader will run
`crates/seam/tests/net_leader.rs`: own block universe (forks, invalid twins, orphans), 3 to 6 peers,
lossy reordering network with a partition that heals, a peer that joins late, convergence on the
leader's fork-choice tip and state root; garbage datagrams and oversize streams; determinism.

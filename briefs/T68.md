# T68 tectonic (crates/tectonic): fixed-point maths, entity system, fixed time step, world hash
Worker: haiku. First read `briefs/_RULES.md` and `crates/tectonic/src/lib.rs`.

**May touch:** `crates/tectonic/**` only (its `Cargo.toml` may add `assay` as a dev-dependency by
path). `no_std` + `alloc`, `#![forbid(unsafe_code)]`, zero external crates, **no floating point
anywhere in `src/`** (tests may use `f64` to measure error).

## Why
The game engine (physics T69, scripting and replays T70) must be bit-for-bit deterministic on
every platform, including WebAssembly later: same inputs, same world hash. So all maths is
fixed point and iteration order never depends on hashing or addresses.

## Public API (exact)
```rust
pub mod fx {
    #[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Default)]
    pub struct Fx(pub i64);                       // Q47.16: value = raw / 65536
    impl Fx {
        pub const ZERO: Fx; pub const ONE: Fx; pub const HALF: Fx; pub const PI: Fx; // PI = round(pi * 65536)
        pub const fn from_int(n: i32) -> Fx;
        pub fn from_ratio(num: i64, den: i64) -> Fx;  // rounded to nearest, ties away from zero; den != 0
        pub fn mul(self, o: Fx) -> Fx;            // i128 intermediate, rounded to nearest, saturating
        pub fn div(self, o: Fx) -> Fx;            // rounded to nearest, saturating; x / 0 saturates by sign (0/0 = 0)
        pub fn sqrt(self) -> Fx;                  // floor of the exact root; negative -> ZERO
        pub fn sin(self) -> Fx; pub fn cos(self) -> Fx; // radians, |error| <= 2/65536 for |x| <= 1000
        pub fn atan2(y: Fx, x: Fx) -> Fx;         // in (-PI, PI], |error| <= 4/65536; atan2(0,0) = 0
        pub fn abs(self) -> Fx; pub fn floor(self) -> Fx; pub fn round(self) -> Fx;
        pub fn to_int(self) -> i64;               // floor
    }
    // core::ops Add Sub Neg (saturating) and Mul/Div calling the methods above.
    #[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Default)]
    pub struct Vec2 { pub x: Fx, pub y: Fx }
    impl Vec2 { pub fn new(x: Fx, y: Fx) -> Vec2; pub fn dot(self, o: Vec2) -> Fx; pub fn cross(self, o: Vec2) -> Fx;
                pub fn len(self) -> Fx; pub fn normalized(self) -> Vec2; /* zero stays zero */ pub fn scale(self, k: Fx) -> Vec2; }
    // Add Sub Neg for Vec2.
}

    pub struct Entity { pub index: u32, pub generation: u32 }
    pub trait Component: core::any::Any + Clone + core::hash::Hash {}
    impl<T: core::any::Any + Clone + core::hash::Hash> Component for T {}
    pub struct World { /* ... */ }
    impl World {

        pub fn alive(&self, e: Entity) -> bool;
        pub fn insert<T: Component>(&mut self, e: Entity, c: T) -> bool; // false for a dead entity; replaces
        pub fn get<T: Component>(&self, e: Entity) -> Option<&T>;
        pub fn get_mut<T: Component>(&mut self, e: Entity) -> Option<&mut T>;

}
```

## Behaviour
- `each`/`each2` visit entities in ascending index order; `each2` only entities holding both.
- `hash`: FNV-1a 64 (your own `core::hash::Hasher`) over, for each alive entity in ascending
  index: index, generation, then each component type in the order that type was first inserted
  into this world, a presence byte and, if present, the component's `Hash` output. Two worlds
  built by the same sequence of calls have the same hash; never depends on `TypeId` values,
  addresses or capacity.
- Despawn removes all of an entity's components. Stale handles (old generation) never see a new
  entity's components.
- Pcg32: `new(seed, stream)` as the reference `pcg32_srandom_r(seed, stream)`; first outputs for
  (42, 54) are `0xa15c02b7 0x7b47f409 0xba1d3330 0x83d2f293 0xbfa4784b 0xcbed606e`.

## Tests required
- `Fx` tables: 30+ hand cases for mul/div rounding and saturation; sqrt exact floor for 10 000
  random values (check `r*r <= x < (r+1)*(r+1)` on raw integers with the scale applied);
  sin/cos/atan2 error bounds over 20 000 points measured against `f64` in the test.
- ECS: spawn/despawn reuse and generations, stale handle cases, `each2` order and filtering,
  replace on insert, remove, despawn clears components.
- Determinism: a seeded simulation (1000 entities, random spawn/despawn/insert/remove, a movement
  system on `Vec2` components, 600 steps) run twice gives the same `hash` every step; a different
  seed differs; the final hash is pinned as a constant in the test.
- Clock: 60 Hz with jittery frame times sums to the right step count; cap drops time; alpha range.

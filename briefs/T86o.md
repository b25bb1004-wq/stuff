# T86o tool (crates/lithium): the `lithium` command-line tool
Worker: hydrogen-high (agy). Budget: one run, at most 90 minutes. First read `briefs/_RULES.md`, then `docs/APPS.md`
(the "Tool conventions" section and the `lithium` row; those rules are part of this brief), then only the public
items of `crates/lithium/src/lib.rs` and the modules they point to that you call. Read nothing else.
**May touch:** `crates/lithium/src/bin/lithium.rs`, `crates/lithium/tests/cli_lithium.rs`, `crates/lithium/Cargo.toml`
(a `[[bin]]` entry or a path dependency already in the workspace, never one that creates a cycle) only. Do not
change library code; if a subcommand needs something the library does not offer, leave it out and say so. Zero
external crates. Your gate is `bash tools/check.sh lithium`; you can only run commands for `lithium`.

## Tool
- `lithium`: `run [--steps N]` boots the lithium OS image on Silicon (`lithium::run`) and prints its console output then `exit:` and the step count; `image -o OUT.bin` writes the assembled image.

## Tests
`tests/cli_lithium.rs` as `docs/APPS.md` says: `--help`, `--version`, every subcommand on a good input, one bad input
each (exit 1 and a `lithium:` message), an unknown subcommand (exit 2). Run `cargo fmt -p lithium` before the gate.

## Report
`reports/T86o.md` (at most 10 lines): subcommands, anything left out and why, tests, gate last line.

## Extra check the leader will run
Release build, the tool by hand on fresh inputs, `bash tools/check.sh lithium`.

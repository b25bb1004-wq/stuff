## New public API (crate root, exact)
```rust
pub const DEPLOY: Address = [0; 32];
pub const FUEL_PER_FEE: u64 = 1000;
pub fn contract_address(deployer: &Address, nonce: u64) -> Address; // sha256(b"seam-contract" || deployer || nonce LE)
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Receipt { pub ok: bool, pub fuel_used: u64, pub events: Vec<String>, pub contract: Option<Address> }
impl Chain {
    pub fn receipts(&self, height: u64) -> Option<&[Receipt]>; // one per tx, genesis has none
    pub fn code(&self, contract: &Address) -> Option<&str>;    // the Mica source
    pub fn storage(&self, contract: &Address, key: &[u8]) -> Option<&[u8]>;
}
```

## Rules
- The T48 tx checks (TooLarge, BadSignature, BadNonce, InsufficientFunds) run first and unchanged;
  then the sender is debited `amount + fee`, its nonce goes up, `fee` goes to the proposer. A
  contract failure never makes a block invalid: it gives `Receipt { ok: false, .. }`.
- **Deploy:** `to == DEPLOY` and `data` non-empty. `data` must be UTF-8 Mica source that parses,
  checks and compiles (`mica::parser::parse`, `mica::check::check`, `sinter::compile`), has `main`,
  and whose module imports are all in the chain set: `chain.get`, `chain.set`, `chain.caller`,
  `chain.emit`, `chain.input` (`-> [byte]`), `chain.value` (`-> int`). Then the contract lives at
  `contract_address(from, nonce_before_this_tx)`, its account is credited `amount`, receipt `ok`,
  `contract: Some(addr)`, `fuel_used: 0`. Otherwise receipt `ok: false` and `amount` goes back to
  the sender (fee and nonce stay spent). `to == DEPLOY` with empty data is a plain transfer.
- **Call:** `to` holds code. `amount` is credited to the contract account, then its `main` runs on
  Geode with fuel `fee * FUEL_PER_FEE` (saturating), heap 1 MiB, depth 64. Host: `chain.input`
  returns `data`, `chain.value` returns `amount`, `chain.caller` returns `from`, `chain.get`/
  `chain.set` read and write this contract's storage, `chain.emit` appends an event. Storage
  writes and events are buffered: on success they apply and receipt `ok: true`; on any trap
  (including out of fuel) they are dropped, `amount` goes back to the sender, receipt `ok: false`.
  `fuel_used` is the VM's fuel used either way. Any other import name traps.
- **State root:** the T48 account leaves, plus one 96-byte leaf per contract
  `address || sha256(source) || storage_root`, where `storage_root = merkle_root` over the
  leaves `len(key) as u32 LE || key || value` sorted by key. All leaves sorted by address, a
  48-byte account leaf before a 96-byte contract leaf of the same address. No contracts: T48 root.
- `propose` and `append` both use these rules; receipts are stored per height on append.
  Everything is deterministic: same blocks, same roots and receipts on every node.

## Tests required
`tests/contracts.rs`: a counter contract (storage key `"n"`, add one per call, emit the value);
a token contract (balances in storage keyed by caller, `input` = recipient 32 bytes + amount 8
bytes LE); deploying source that uses `io` or `print` rejected (`ok: false`, no code, amount
refunded); unparsable source rejected; a call that runs out of fuel and one that traps both
revert storage and refund `amount`, fee still paid; three `Chain`s fed the same blocks through
`Block::encode`/`decode` reach equal state roots and receipts; a chain with no contracts gives the
same roots as T48.

## Build
- Door driver in a new `kernel/door.rs`: map `0x1000_4000` (size `0x1000`) in the kernel page table like
  the other MMIO ranges; send = copy the user bytes into a kernel buffer, set TX_ADDR (physical), TX_LEN,
  TX_CHAN, write TX_GO, check STATUS bit 1; receive = read STATUS bit 0, RX_LEN, RX_CHAN; set RX_ADDR to a
  kernel buffer (RX_CAP 1 MiB or smaller, your choice, document it), write RX_TAKE, copy to the user buffer.
- Calls exactly as C2: 16 `result`, 22 `door_send`, 23 `door_recv` (non-blocking, -7 if empty), 25
  `child_result`. The door right (P1): a process whose program name is `hermes` or `doorecho` (test
  program). Everyone else gets -1 from 22 and 23.
- `result`: keep the last value per process (max 64 KiB, must be UTF-8). On exit it moves to the zombie
  slot; `child_result` copies it for the parent after `wait`, and it is freed when fetched or when the
  parent exits.
- Test programs in assembly (same style as `ping.s`): `doorecho.s` (loop: `door_recv` into a buffer, on
  -7 `yield`, on a frame `door_send` it back on the same channel, prefixed with nothing; exit after 2
  frames), `resulty.s` (calls `result` with `{"ok":true}` and exits 0), `resultp.s` (spawns `resulty`,
  waits, calls `child_result`, writes the bytes to stdout, exits 0), `doorbad.s` (not named hermes: calls
  `door_send`, writes `refused` to stdout if the result is -1).

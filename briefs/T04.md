## Public API (exact)
```rust
// lib.rs: add to the existing enum, keep the old variants
pub enum Error { BadTag, BadLength, WeakKey, BadSignature }

pub mod x25519 {                                       // RFC 7748
    pub fn public_key(secret: &[u8; 32]) -> [u8; 32];
    pub fn shared_secret(secret: &[u8; 32], peer_public: &[u8; 32]) -> Result<[u8; 32], Error>; // WeakKey if the result is all zero
}
pub mod ed25519 {                                      // RFC 8032, pure Ed25519 (no context, no prehash)
    pub fn public_key(seed: &[u8; 32]) -> [u8; 32];
    pub fn sign(seed: &[u8; 32], message: &[u8]) -> [u8; 64];
    pub fn verify(public: &[u8; 32], message: &[u8], signature: &[u8; 64]) -> Result<(), Error>; // BadSignature
}
```

## Requirements
- Field arithmetic mod 2^255 - 19 in 51-bit limbs (`[u64; 5]`, products in `u128`), shared by
  both algorithms. Scalar arithmetic mod the group order L for Ed25519.
- **Constant time for secrets:** the X25519 ladder uses a masked conditional swap; Ed25519 key
  generation and signing use a scalar multiplication whose sequence of operations and memory
  accesses does not depend on the scalar (for example a double-and-add-always ladder with
  masked selection, or a fixed window with masked table lookup). No `if` or early exit on
  secret bits, no secret-indexed table lookups. Field reduction and inversion are fixed-sequence.
  `verify` handles only public data and may be variable time.
- `verify` rejects: a signature whose S is not below L (malleability), an R or public key that
  does not decode to a curve point, and non-canonical encodings of the y coordinate (y >= p).
  It uses the cofactorless equation [S]B = R + [k]A, comparing encoded points.
- X25519 clamps the secret as the RFC says and masks the top bit of the peer's u coordinate.

## Tests required
- RFC 7748: both section 5.2 vectors; the iterated test after 1 and after 1000 iterations; the
  section 6.1 Diffie-Hellman example (both public keys and the shared secret).
- RFC 8032 section 7.1: TEST 1, TEST 2, TEST 3, TEST 1024 and TEST SHA(abc): public key and
  signature bytes must match exactly, and verify must accept.
- Properties (`forall`): `shared(a, pub(b)) == shared(b, pub(a))`; sign then verify succeeds for
  random seeds and messages of length 0 to 300; flipping any single bit of the signature, the
  message or the public key makes verify fail; adding L to S makes verify fail; the all-zero
  peer key gives `WeakKey`.
- Field tests: `a * inverse(a) == 1` for random a; encode/decode round trip; values at and just
  above p reduce correctly.

Only use RFC vectors you are sure of. If one fails, check the vector against a second vector
before changing code that looks right, and say in the report which you could not confirm.

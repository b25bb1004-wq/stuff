## Why
The Rust kernel (T25) needs `#[global_allocator] static HEAP: Locked<Heap> = Locked::new(Heap::empty());`
and gives it memory during boot. Page tables and DMA buffers need alignments above 4 KiB.

## Public API (added; the T02 API stays exactly as it is)
```rust
pub const MAX_ALIGN: usize = PAGE << 10;            // largest supported alignment = largest buddy block (4 MiB)
impl Buddy {
    pub const fn empty() -> Buddy;                   // no memory: alloc_pages returns None, free_bytes 0
    pub fn check(&self) -> bool;                     // now public (it exists as pub(crate))
}
impl Heap {
    pub const fn empty() -> Heap;                    // no memory: every non-zero-size alloc returns null
    /// # Safety: the same contract as `Heap::new`.
    pub unsafe fn init(&mut self, base: *mut u8, len: usize) -> bool;  // false (and no change) if
                                                     // already initialised or the region is too small
    pub fn is_ready(&self) -> bool;                  // true after a successful `new` or `init`
    pub fn total_bytes(&self) -> usize;              // the buddy's usable bytes; 0 when empty
}
impl Locked<Heap> {
    /// # Safety: the same contract as `Heap::new`.
    pub unsafe fn init(&self, base: *mut u8, len: usize) -> bool;      // lock, then Heap::init
}
```

## Behaviour
- Big alignments: any power-of-two alignment up to `MAX_ALIGN` works for any size the buddy can
  hold. The returned address must be aligned in absolute terms, not relative to the region start:
  today a block of order k is aligned to 2^k pages counted from the region base, which is only
  page aligned. Fix the tiling and the buddy arithmetic so an order-k block always starts at an
  address that is a multiple of `PAGE << k` (pages that cannot form an aligned block become
  smaller blocks, as the tail already does). Alignment above `MAX_ALIGN`, or a size above the
  largest block, returns null. `used_bytes` stays exact.
- `check()` (both `Buddy` and `Heap`) must be safe to call on corrupted memory: bounds-check every
  link before reading through it, bound every walk, never panic, never read outside the region.
  It returns false for at least: a free-slot link outside the region, misaligned for its class,
  or inside a page that is not a slab page of that class; a cycle in any list; a buddy link to a
  page that is out of range, misaligned for its order, or whose table entry disagrees; a free sum
  that disagrees with `free_bytes`; a slab page whose live count disagrees with its free slots.
- Empty heap: `alloc` returns null, `dealloc` of a zero-size layout is ignored, `check()` is true.

## Tests required
- Const: a `static` `Locked<Heap>` built from `Heap::empty()` in a test, initialised later through
  `Locked::init`; a second `init` returns false and changes nothing.
- Global allocator: a separate integration test binary (`tests/global.rs`) whose
  `#[global_allocator]` is quarry. Back it with a static, 4 MiB-aligned arena of at least 64 MiB.
  A small lazy-init wrapper in the test file that calls `Locked::init` on the first allocation is
  fine. In it: `Vec`, `String`, `Box`, `HashMap` work; 4 threads x 5000 random ops with the
  tag-byte check; `check()` true at the end.
- Big alignments (`forall`, 200 cases): random sizes 1..=1 MiB and alignments up to `MAX_ALIGN`,
  over arenas that start at deliberately odd page offsets; every pointer is absolutely aligned,
  live blocks never overlap, tag bytes survive, and freeing everything restores `free_bytes`.
- Corruption (`forall`, 500 cases): build a heap, churn, then write random words into random free
  slots and free buddy blocks (through the raw pointers the test owns); `check()` must return
  false or true without panicking, and must return false for each listed corruption done on purpose.

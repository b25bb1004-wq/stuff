## Design (fixed by the leader)
- `kernel/blk.rs`: `struct Blk` implementing `hades::BlockDevice` over the MMIO block device, polling, one hades block
  per request (`BLOCK / 512` sectors), DMA through a kernel bounce buffer. `flush` is a no-op that returns Ok.
- Boot: if the device reports capacity 0, behave exactly as T26 (same 34-line transcript, no new lines). Otherwise
  `Fs::mount` it and print `fs: mounted <block_count> blocks` immediately after the 11 T25 lines. A mount error prints
  `fs: mount failed` and continues as if there were no disk.
- Open flags: `1` read, `2` write, `4` create, `8` truncate (OR-able). fd table per process, fds 3..=15, closed on exit.
  Each open file keeps (path, offset, flags). `read`/`write` on a file fd move the offset. `open("/")` or any directory
  with flag 1 gives a directory fd for `readdir`.
- `readdir(fd, buf, len)`: writes names (sorted, as hades lists them) each followed by `\n`, as many whole names as fit,
  continuing from where the previous call stopped; returns bytes written, 0 at the end, -1 if one name does not fit.
- `mkdir` on an existing path gives -5. `unlink` removes a file or an empty directory; a non-empty directory gives -7. Errors use the TITAN.md table: missing path -2, bad fd -4, exists -5, not a directory -6, busy -7,
  bad pointer or flags -1. All user pointers go through `titan::uaccess`.
- `init` spawns `fsdemo` after `evil` and before the ps line, only when `open("/", 1)` succeeds (close it after).

## fsdemo transcript (exactly these lines, only with a disk; the test disk holds `/hello.txt` = `hello`)
```
fsdemo: read hello
fsdemo: wrote 5
fsdemo: ls a.txt dir hello.txt
fsdemo: errors ok

```
`fsdemo` reads `/hello.txt`, creates `/a.txt` with `world`, `mkdir /dir`, lists `/` with readdir, checks
`open("/nope",1) == -2`, `mkdir("/dir") == -5`, `read(99,..) == -4`, then unlinks `/a.txt`.

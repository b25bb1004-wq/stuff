## Why
The interpreter in `mica::eval` is the oracle. Geode is the VM that blockchain contracts (T49),
scripting (T67, T70) and the browser playground (T71) run. This task makes every Mica program run
on Geode and print exactly what the oracle prints.

## Public API (exact)
```rust
// crates/geode: the only change there
impl Vm { pub fn trap_site(&self) -> Option<(u32, u32)>; }  // (func index, op index) of the op
                                                             // that raised the last trap; None after a clean run
// crates/sinter
pub struct Compiled {
    pub module: geode::Module,
    pub main: Option<u32>,                 // geode func index of `main`
    pub tests: Vec<(String, u32)>,         // same order as ir::Program::tests
    pub props: Vec<CompiledProp>,          // same order as ir::Program::props
    pub spans: Vec<Vec<mica::Span>>,       // spans[func][op] = source span of that op
}
pub struct CompiledProp { pub name: String, pub guard: Option<u32>, pub body: u32,
                          pub params: Vec<mica::ir::Ty> }
pub fn compile(p: &mica::ir::Program) -> Compiled;            // never fails on checked IR
pub fn run_main(c: &Compiled, input: &str, fuel: u64) -> mica::eval::Outcome;
pub fn run_test(c: &Compiled, index: usize, fuel: u64) -> mica::eval::Outcome;
pub fn run_prop(c: &Compiled, index: usize, seed: u64, cases: u32, fuel: u64) -> mica::eval::Outcome;
```
(`mica::Span` and `mica::line_col` are already public.)

## Behaviour
- **Same answers as the oracle.** For every checked program and enough fuel, `sinter::run_*`
  returns the same `Outcome` as `mica::eval::run_*`: same `output`, same trap kind, same span.
  Fuel counts differ between the two and are not compared; `OutOfFuel` only when fuel runs out.
- The compiled module passes `geode::verify`, and `decode(&encode(&m)) == Ok(m)`.
- Traps map one to one (`Overflow`, `DivideByZero`, `IndexOutOfRange`, `AssertFailed(msg)`,
  `OutOfFuel`, `StackOverflow`). Call depth limit 10 000, as the oracle. A missing extern is
  `NoExtern(name)` when it is called, not at load: load the module with all its imports and
  let the host trap on unknown names. Geode `TypeError`, `OutOfMemory` or `User` from compiled
  code is a compiler bug: never produce them.
- The span of a trap comes from `vm.trap_site()` and `spans`.
- Host: `io.print`, `io.read_line`, `time.now` (0), `rand.next` with the oracle's exact sequence
  (copy its generator). Props draw arguments with the oracle's exact generator (copy it) so that a
  failing seed fails at the same case with the same `output`.
- `mica` binary: `mica run FILE [--fuel N]` (stdin feeds `io.read_line`, output to stdout, a trap
  prints `trap: <kind> at LINE:COL` to stderr and exits 1; a parse or check error prints
  `FILE:LINE:COL: message` and exits 2). `mica test FILE [--seed N] [--cases N]` runs every test
  and prop, prints `ok NAME` or `FAIL NAME: ...` per item and a last line `N passed, M failed`,
  exit 0 only when nothing failed. Defaults: fuel 100 000 000, seed 1, cases 100.

## Build
1. **atlas heap that frees.** hermes runs forever, so the bump allocator would leak. In
   `crates/atlas/src/titan/heap.rs`: on the first allocation `sbrk` one arena of 4 MiB and hand it to
   `midas::Locked<midas::Heap>` (`init(base, len)`); allocations and frees go through midas; if the arena
   is full return null (no growth in v1, note it as `shortcut:`). Add `midas = { path = "../midas",
   default-features = false }`. `bash tools/check.sh atlas` must still pass and the riscv build of atlas
   must still succeed.
2. **hermes crate** `crates/hermes`: a binary `hermes`, program shape from C3
   (`#![cfg_attr(target_os = "none", no_std, no_main)]`, `atlas::main!(run)`), deps `atlas`, `aci`.
   Loop: `door_recv` on a 1 MiB buffer (call 23; add a tiny `door` module in hermes with the `ecall`
   wrappers for 22 and 23, `unsafe` only there with `// SAFETY:`); on -7 call `yield` (call 9) and loop.
   Each frame is one C4 request (JSON via `aci::json::Json::parse`). Handle `run`, `read`, `write`
   exactly as C4: `run` opens `/tmp/hermes-<id>.out` for writing (create `/tmp` if missing), spawns
   `argv[0]` with `argv[1..]` and that fd as stdout, waits, reads the file back, gets `child_result`,
   removes the file, replies with `{"id","ok":true,"exit","stdout","result"}`; stdout over 256 KiB is cut
   with `[cut N bytes]`. Any failure replies `{"id","ok":false,"error":"..."}` (id null if unparsable);
   hermes never exits on a bad request. Reply with `door_send` on channel 0.
   Host build: `run()` prints `hermes: titan only` and returns 2 (so workspace host builds and clippy
   pass). Pure logic (request parsing, reply building, the stdout cut) lives in a module with host unit
   tests.
3. **Embed in Titan:** `crates/titan/build.rs` builds `hermes` and `calliope` for
   `riscv64gc-unknown-none-elf` with `user.ld`, the same nested-cargo way it builds `userland` (one
   nested build for both is fine), copies them to `OUT_DIR/hermes.elf` and `OUT_DIR/calliope.elf`;
   `progs.rs` maps `"hermes"` and `"calliope"`. The door right in the kernel already allows `hermes`.
4. **Start it:** `init.s` spawns `hermes` (and does not wait for it) only when `open("/etc/hermes", 1)`
   succeeds, the same pattern as `/etc/shell`. Existing boot tests have no `/etc/hermes` and stay unchanged.

containing `/etc/hermes` and `/w/a.txt` = "alpha\nbeta\ngamma\n")

2. `write` then `read` of `/w/b.txt` round-trips the text.
3. A garbage frame gets `"ok":false`, and a following valid request still works.
4. 50 `read` requests in a row all succeed (proves the heap frees).
5. Gates: `bash tools/check.sh hermes`, `bash tools/check.sh atlas`, `bash tools/check.sh titan` all end
   with CHECK PASS.

## Design (fixed by the leader)
- Library (`src/lib.rs` + modules), every service as a function the tests can run in a thread:
  - `shutdown`: `pub fn install()` registers SIGTERM and SIGINT on Unix (`extern "C" fn signal`, handler only
    stores to a static `AtomicBool`); no-op elsewhere. `pub fn requested() -> bool`, `pub fn request()`.
  - `probe`: `pub fn tcp(addr: &str, timeout: Duration) -> Result<(), String>`,
    `pub fn http(addr: &str, path: &str, timeout: Duration) -> Result<String, String>` (GET, Ok(body) only on 200).
  - `pub fn run_iridium(listen: &str, data: &Path, stop: &AtomicBool, ready: impl FnOnce(SocketAddr))`,
    `pub fn run_registry(listen: &str, publishers: Vec<[u8; 32]>, stop, ready)`,
    `pub fn run_aurum(cfg: &AurumConfig, stop, ready)`; each returns `Result<(), String>`, polls `stop` at least every
    100 ms, then calls the server's `stop()` and returns. `ready` gets the bound address (the health address for
    aurum).
  - `AurumConfig { id: u8, listen: String, health: String, peers: Vec<(u8, String)>, validators: u8 }`. Validator
    `i` (1..=validators) has secret `sha256("monolith-demo-validator-" + i)`: demo keys, documented as public and
    not secret. Genesis gives each validator 1_000_000. The node binds a `UdpSocket` on `listen`, drives `Peer`
    (`receive`, `poll_transmit`, `timeout`/`on_timeout`), proposes when it is its turn, and serves HTTP on `health`
    through mercury: `GET /health` -> 200 `height=<n> tip=<hex> peers=<n>`.
- Binaries (`src/bin/`), flags only, errors to stderr with exit 2, a service error exit 1, clean stop exit 0:
  `iridium-server --listen ADDR --data DIR`, `argo-registry --listen ADDR [--publisher HEX64]...`,
  `aurum-node --id N --listen ADDR --health ADDR --validators N [--peer ID@HOST:PORT]...`,
  `healthcheck tcp ADDR` / `healthcheck http ADDR PATH` (exit 0 healthy, 1 not; 2 s timeout). Each service binary
  calls `shutdown::install()` first and logs one line on start (`listening on ...`) and one on stop.
- `crates/deploy/docker/Dockerfile` (build context = repository root): stage `build` from `rust:1.98-alpine`,
  `cargo build --release --locked -p deploy` (musl, static), then three final stages `FROM scratch`: `iridium`,
  `registry`, `aurum`, each with its binary plus `healthcheck`, `USER 65534:65534`, `ENTRYPOINT` the service,
  `HEALTHCHECK` using `healthcheck` (exec form; there is no shell). `crates/deploy/docker/Dockerfile.dockerignore`
  excludes `target`, `.git`, `graphify-out`, `.loop-local`, `**/target`.
- `crates/deploy/docker/compose.yaml`: services `iridium` (named volume at `/data`), `registry`, `aurum1`..`aurum3`
  (each peers with the other two by service name; 3 validators), healthchecks every 2 s, `stop_grace_period: 10s`,
  ports published on `127.0.0.1` only (iridium 7400, registry 7500, aurum health 7601-7603). No `privileged`, no
  host network, `read_only: true` with a tmpfs only where needed.
- `crates/deploy/README.md`: what runs, ports, `docker compose -f crates/deploy/docker/compose.yaml up --build -d`,
  how to check health, that the validator keys are public demo keys.

## Tests
- `tests/services.rs` (all platforms, loopback, ports `127.0.0.1:0`):
  - iridium: start in a thread, `probe::tcp` ok, a `Client` creates a table and inserts a row, `request` stop, thread
    returns Ok within 2 s; start again on the same data dir and the row is still there.
  - registry: `probe::http(addr, "/index")` ok; stop within 2 s.
  - aurum: 3 nodes peered on loopback; within 20 s all three `/health` report the same tip and height >= 3; stop all
    within 2 s.
  - probe: `tcp` and `http` fail with an error (not hang) on a closed port within the timeout.
  - flag parsing for each binary (a pure `parse_args(&[String]) -> Result<_, String>` per binary): good and bad cases.
- Unix-only (`cfg(unix)`), skipped on Windows: spawn the built `iridium-server` binary
  (`env!("CARGO_BIN_EXE_iridium-server")`), wait for `listening`, send SIGTERM through `extern "C" kill`, it exits 0
  within 3 s.

## Build
- Porting rule: core logic stays; only the edges move. Under `target_os = "none"` the crates are
  `no_std` + `alloc` (`#![cfg_attr(target_os = "none", no_std)]`); on the host everything stays as today.
- aci: make it compile for `riscv64gc-unknown-none-elf` (use `alloc` types; anything that needs std, like
  reading files, goes behind `#[cfg(not(target_os = "none"))]`). Host behaviour and tests unchanged.
- calliope library: the modules `grep` and `edit` need (regex, buffer and whatever else) compile for
  titan; the interactive editor (terminal, screen, keys, session, highlight, logos dependency) is
  host-only behind `#[cfg(not(target_os = "none"))]`. Make the `logos` dependency target-specific
  (`[target.'cfg(not(target_os = "none"))'.dependencies]`).
- calliope binary: the `grep` and `edit` subcommands (and `--help`, and the aci flags they already
  support) use `atlas` for args, files, output and exit, on both targets; add `atlas = { path = "../atlas" }`.
  The interactive editor path stays host-only. On titan, an unknown or host-only subcommand prints an
  error envelope and exits 2.
- Program shape on titan: `#![cfg_attr(target_os = "none", no_std, no_main)]`, `atlas::main!(run)`.

## Accept
1. All existing calliope and aci tests pass on the host (no test deleted or weakened).
2. `CARGO_TARGET_DIR=target/w-calliope-rv cargo build -p calliope --bin calliope --release --target riscv64gc-unknown-none-elf --config "target.riscv64gc-unknown-none-elf.rustflags=['-C','link-arg=-Tcrates/titan/user.ld']"`
   succeeds (run from the repository root; if the linker-script path must be absolute, use the absolute path
   and say so).
3. Gates: `bash tools/check.sh aci` and `bash tools/check.sh calliope` both end with CHECK PASS.

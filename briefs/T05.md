# T05 geyser: fair scheduler core and simulator tests

**May touch:** `crates/geyser/**` only. `#![forbid(unsafe_code)]` stays.
The crate is `#![cfg_attr(not(test), no_std)]` with `extern crate alloc;`.
Geyser decides which task runs on which CPU and for how long. It is pure logic: no threads, no
clocks, no I/O. The caller passes the time in. The OS kernel, the hypervisor and the thread pool
will all drive this same core.

## Public API (exact)
```rust
pub type TaskId = u32;
pub struct Config { pub latency_us: u64, pub min_slice_us: u64 }   // impl Default: 6000, 750
pub enum Class { Realtime { prio: u8 }, Normal { nice: i8 }, Idle }  // nice is clamped to -20..=19
pub enum State { Ready, Running, Blocked, Dead }
pub enum Error { NoSuchTask, BadCpu, BadState, TooManyTasks }      // Debug, Clone, Copy, PartialEq, Eq
pub struct Decision { pub task: Option<TaskId>, pub slice_us: u64 } // None means the CPU idles
pub struct Stats { pub state: State, pub class: Class, pub runtime_us: u64, pub switches: u64, pub cpu: Option<usize> }
pub struct Scheduler;
impl Scheduler {
    pub fn new(cpus: usize, config: Config) -> Scheduler;           // cpus is clamped to 1..=64
    pub fn spawn(&mut self, class: Class, affinity: u64, now_us: u64) -> Result<TaskId, Error>; // bit i set = CPU i allowed; 0 = any CPU
    pub fn pick(&mut self, cpu: usize, now_us: u64) -> Result<Decision, Error>;
    pub fn block(&mut self, task: TaskId, now_us: u64) -> Result<(), Error>;   // Running or Ready -> Blocked
    pub fn wake(&mut self, task: TaskId, now_us: u64) -> Result<(), Error>;    // Blocked -> Ready; BadState otherwise
    pub fn exit(&mut self, task: TaskId, now_us: u64) -> Result<(), Error>;    // any live state -> Dead
    pub fn set_class(&mut self, task: TaskId, class: Class) -> Result<(), Error>;
    pub fn stats(&self, task: TaskId) -> Result<Stats, Error>;
    pub fn runnable(&self) -> usize;                                // tasks that are Ready or Running
}
```
All public types derive `Debug, Clone, Copy, PartialEq` where possible.

## Behaviour
- `pick(cpu, now)` first charges the task now running on that CPU for the time since it was
  picked, puts it back in the queue if it is still runnable, then chooses the next task and marks
  it `Running` on that CPU. Time that goes backwards is treated as no time passed.
- Order of classes: any ready `Realtime` task beats every `Normal` task; `Idle` tasks run only
  when nothing else is ready. Realtime: higher `prio` first, round robin among equals.
- Normal tasks are weighted fair: each has a virtual runtime that grows by
  `real_time * 1024 / weight`, and the smallest virtual runtime runs next (ties: lower TaskId).
  Weight table: nice 0 is 1024, and each nice step is a factor of about 1.25 (write the 40
  values as a constant table). Slice = `max(min_slice, latency / ready_normal_on_this_cpu)`.
- A task that wakes gets `max(own virtual runtime, queue minimum - latency / 2)` so a long
  sleeper cannot starve the others, and a short sleeper keeps a small bonus.
- One run queue per CPU. A new or woken task goes to the allowed CPU with the fewest runnable
  tasks. A CPU whose queue is empty steals the task with the smallest virtual runtime from the
  busiest queue whose tasks are allowed to run on it.
- A `Dead` id is never reused. More than 65 536 live tasks gives `TooManyTasks`.
- No call panics, whatever the arguments or their order. Same calls give the same decisions.

## Tests required
Build a small simulator in the test module: a list of CPUs, a clock, and tasks that run for a
given burst and then block for a given time. Then, with `forall`:
- Fairness: N CPU-bound tasks with equal nice on one CPU differ in runtime by at most one slice
  after a long run. Nice 0 against nice 5 gives a runtime ratio within 5 percent of the weights.
- Classes: a ready realtime task is always picked before any normal task; an idle task never
  runs while a normal task is ready on a CPU it could use.
- No starvation: every ready normal task runs within `latency * (tasks on that CPU + 1)`.
- Affinity is never broken. Work conservation: after `pick`, no CPU idles while a ready task
  that may run on it exists.
- Invariants under random call sequences (at least 300 cases of 500 calls, with bad ids, bad
  CPUs and time going backwards): a task runs on at most one CPU, a dead task is never picked,
  the sum of all `runtime_us` equals the total busy time of the CPUs, and `runnable()` matches
  a count made through `stats`.
- Determinism: replaying a call sequence gives identical decisions.

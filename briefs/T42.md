## Wire protocol (exact; the leader writes its own client)
- Every frame is a u32 big-endian length then that many bytes. Frames over 1 MiB, or bytes that are
  not a whole frame when the peer closes, end the connection (no reply).
- Request frame: one SQL statement, UTF-8 (invalid UTF-8: error reply).
- Reply frame: `0x00` then `encode_rows`, or `0x01` then the error message UTF-8.
- `encode_rows`: u64 BE changes, u32 BE column count, each name as (u32 BE len, bytes), u32 BE row
  count, then every value: `0` Null, `1` Int (i64 BE), `2` Text (u32 BE len, bytes), `3` Blob
  (u32 BE len, bytes). `decode_rows` rejects trailing bytes, short input and rows of the wrong width.

## Concurrency (exact)
- One `Db` behind a mutex; one thread per connection; statements run one at a time.
- A connection that runs `BEGIN` holds the database until its `COMMIT` or `ROLLBACK`; other
  connections wait. A wait longer than 2 seconds replies `0x01` + `busy`. A connection that closes
  inside a transaction is rolled back. `stop` rolls back open transactions.
- Data survives `stop` and a new `start` on the same files.

## iridium-cli
`iridium-cli <host:port>` reads statements from stdin, one per line (blank lines skipped), prints each
result row as tab-separated values (NULL as `NULL`, blobs as `x'hex'`), then `ok <changes>`;
errors print `error: <message>` and the tool continues. Exit code 0 at end of input.

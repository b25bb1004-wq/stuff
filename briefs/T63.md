## API (exact)
```rust
pub type WinId = u32;
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub enum Layout { Floating, Tiling }
/// Where an input went after the compositor handled its own shortcuts.
#[derive(Debug, Clone, PartialEq, Eq)] pub enum Routed { ToWindow(WinId, indium::Event), Handled, Dropped }
pub struct Compositor { /* private */ }
impl Compositor {
    pub fn new(width: u32, height: u32) -> Self;
    pub fn open(&mut self, title: &str, w: u32, h: u32, now_ms: u64) -> WinId;   // new window on top, focused
    pub fn close(&mut self, id: WinId, now_ms: u64) -> bool;
    pub fn surface_mut(&mut self, id: WinId) -> Option<&mut pigment::Canvas>;  // client content; damages the window
    pub fn damage(&mut self, id: WinId, r: pigment::Rect);                     // partial client damage, window coords
    pub fn set_layout(&mut self, l: Layout, now_ms: u64);
    pub fn move_to(&mut self, id: WinId, x: i32, y: i32, now_ms: u64);       // animated, 180 ms, Ease::OutCubic
    pub fn resize(&mut self, id: WinId, w: u32, h: u32, now_ms: u64);
    pub fn raise(&mut self, id: WinId);
    pub fn focused(&self) -> Option<WinId>;
    pub fn order(&self) -> Vec<WinId>;                                         // bottom to top
    pub fn rect(&self, id: WinId) -> Option<pigment::Rect>;                    // current (animated) frame rect
    pub fn input(&mut self, ev: indium::Event, super_held: bool, now_ms: u64) -> Routed;
    pub fn frame(&mut self, now_ms: u64) -> Vec<pigment::Rect>;                // advance, composite, return damage
    pub fn screen(&self) -> &pigment::Canvas;
}
```
## Behaviour
- Windows have a 1 px border and an 18 px title bar drawn by iris (colours are constants), content below it.
- Floating: click focuses and raises; drag on the title bar moves (no animation while dragging); windows may be
  partly off screen. Tiling: master and stack (first window left half, the rest split the right half
  evenly, top to bottom, in open order); switching layout animates every window to its new rect.
- Keys (indium has no modifiers, so the caller passes `super_held`): with `super_held`: `Key::Tab` / `Key::ShiftTab`
  focus the next / previous window (and raise it in floating); `Text('[')` / `Text(']')` move the focused window one
  place earlier / later in the tiling order. All of these return `Handled`. Other keys go to the focused window; pointer events go to the topmost window under the pointer, in
  window content coordinates; on desktop background they are `Dropped`.
- `frame` composites only damaged areas, bottom to top, onto a desktop colour, and returns the damaged screen
  rects (merged, clipped to the screen, no zero-size rects). Nothing changed means an empty Vec.
- Damage must equal changed pixels: every pixel that differs from the previous frame lies inside a returned rect,
  and the returned area is at most 2x the true changed area plus 4096 px per rect (no "damage everything").

## Design (fixed by the leader)
- `src/lib.rs`: `pub struct Sample { pub suite: &'static str, pub name: String, pub unit: &'static str, pub ops: u64,
  pub secs: f64 }` with `pub fn rate(&self) -> f64` (ops / secs, 0 when secs is 0).
  - `pub fn measure(suite, name, unit, budget: Duration, f: impl FnMut() -> Result<u64, String>) -> Result<Sample, String>`:
    calls `f` (each call returns the ops it did) until `budget` has elapsed, at least once; times with `Instant`.
  - `pub fn table(samples: &[Sample]) -> String`: a Markdown table `| suite | benchmark | rate | unit |`, rate with
    3 significant digits and k/M suffix (`12.3k`, `4.56M`).
  - `pub struct Opts { pub budget: Duration, pub scale: u32 }` (`scale` multiplies dataset sizes; quick = 1, full = 10).
- One module per suite, each `pub fn run(opts: &Opts) -> Result<Vec<Sample>, String>`. **Every benchmark checks its
  own results** (a lookup finds the value written, a response has status 200 and the right body length, a received
  byte stream equals what was sent, a merkle proof verifies); a wrong result is an `Err`, never a fast number.
  - `mercury`: `parse_request` of a realistic 400-byte GET with 12 headers (requests/s); `write_response` of a 1 KiB
    body (responses/s); a mercury server on `127.0.0.1:0` with one route, 4 client threads on keep-alive
    connections (requests/s), shut down cleanly.
  - `iridium`: `Tree` on `MemStorage`: sequential insert of `20_000 * scale` keys, random insert, point lookups
    (all hit), a full range scan (keys/s); one `FileStorage` run under `std::env::temp_dir()` with commits every
    1000 inserts (inserts/s), directory removed afterwards.
  - `xenon`: loopback server + connection: bulk transfer of `4 MiB * scale` (MB/s, unit `MB/s`, ops = bytes / 1e6
    rounded down is fine if documented, or report bytes and convert in `rate`; your choice, documented), and
    small-message round trips (64 B echo, round trips/s).
  - `aurum`: `merkle_root` over 1024 leaves (roots/s), `merkle_proof` + `merkle_verify` (proofs/s), signed `Tx`
    verification (tx/s), building and applying blocks of 100 transfers to a `Chain` (blocks/s).
- `src/bin/bench.rs`: `bench [--full] [--only SUITE]...`; prints one header line (`cores: N, os: <std::env::consts::OS>,
  budget: ..ms`) then the table. Quick budget 200 ms per benchmark, full 2 s. Unknown flag or suite: usage on stderr,
  exit 2. A suite error: message on stderr, exit 1.

## Tests
- `tests/bench.rs`: `measure` runs at least once and sums ops, respects the budget (a 30 ms budget ends within 1 s);
  an `Err` from `f` propagates; `table` formatting for known samples (exact string); `rate` with secs = 0.
- Each suite's `run` with `Opts { budget: 5 ms, scale: 1 }` returns its samples, all with `ops > 0` and finite rate.
- A broken check is caught: give `measure` an `f` that returns `Err("mismatch")` and assert the error text.

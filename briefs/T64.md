## Design (fixed by the leader)
- `pub trait App { fn title(&self) -> &str; fn event(&mut self, ev: indium::Event, now_ms: u64) -> Effect; fn paint(&mut self, c: &mut Canvas) -> Option<Rect>; }`
  `paint` draws the window content (size = the window's content area) and returns the damaged rect, or None if unchanged.
  `pub enum Effect { None, Close, Open(Box<dyn App>) }`.
- `pub struct Desktop { comp: Compositor, apps: BTreeMap<WinId, Box<dyn App>> }` with `new(w, h)`, `launch(app, w, h, now)`,
  `input(ev, super_held, now)` (routes `Routed::ToWindow(id, ev)` to that app; applies its Effect), `frame(now) -> Vec<Rect>`
  (calls `paint` for each app, forwards damage, then `Compositor::frame`), and `screen()`.
- Text: a fixed 8x16 cell grid drawn with the indium text renderer; the same font everywhere.
- `Terminal`: a krypton `Shell` with an in-memory environment; typed text builds a line, Enter runs it, output lines scroll
  (keep the last 200). Prompt `$ `. `exit` returns `Effect::Close`.
- `Editor`: a calliope buffer: typing inserts, arrows move, Backspace deletes, Ctrl+S saves into the shared hades `Fs`
  (path given at launch). Title shows `*` while unsaved.
- `Files`: lists a directory of the shared hades `Fs` (a `MemDisk` made by `Desktop::new`), Up/Down select, Enter on a
  directory enters it, Enter on a file opens an `Editor` on it (`Effect::Open`).
- Keyboard shortcut `Super+Enter` launches a Terminal (handled by Desktop, not the compositor).

## Tests (`tests/desktop.rs`)
- Scripted session, deterministic (fixed times): launch Files, open `/notes.txt`, type `hello`, Ctrl+S, close; launch a
  Terminal, run `echo hi`, see `hi` in its grid; tiling layout with 3 windows. Assert app state (buffer text, file
  contents read back from the Fs, terminal lines) and that `frame` damage covers every changed pixel (compare two screens).
- Golden frames: a 64-bit FNV hash of `screen().pixels` at 3 points of the session, written in the test as constants.
- An `assay::forall` of random key and mouse events over a Desktop with all three apps: never panics, damage always
  covers changed pixels.
- README and `examples/demo.rs` (prints the session's text state and the 3 frame hashes).

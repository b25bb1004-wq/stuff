## Public API additions (exact)
- `Cpu` gets `pub virt: bool` (the V bit; false at reset). `Mode::Supervisor` with `virt` is VS,
  `Mode::User` with `virt` is VU. `Cpu::new` leaves `virt == false`.
- `Trap` gets `InstGuestPageFault { gva: u64, gpa: u64 }`, `LoadGuestPageFault { gva: u64, gpa: u64 }`,
  `StoreGuestPageFault { gva: u64, gpa: u64 }` (causes 20, 21, 23; `gva` goes to the trap value,
  `gpa >> 2` to htval or mtval2) and `VirtualInstruction(u32)` (cause 22, trap value = the
  instruction bits, as for IllegalInstruction). Ecall from VS is cause 10 (VU stays 8).
- `Inst` gets `Hlv { rd: u8, rs1: u8, width: u8, unsigned: bool, exec: bool }` (width 1, 2, 4 or 8;
  `exec` = HLVX), `Hsv { rs1: u8, rs2: u8, width: u8 }`, `HfenceVvma { rs1: u8, rs2: u8 }`,
  `HfenceGvma { rs1: u8, rs2: u8 }`, with `encode` and decode. Encodings (checked with LLVM):
  hlv.b `0x6000_4073`, hlv.bu `0x6010_4073`, hlv.h `0x6400_4073`, hlv.hu `0x6410_4073`, hlvx.hu
  `0x6430_4073`, hlv.w `0x6800_4073`, hlv.wu `0x6810_4073`, hlvx.wu `0x6830_4073`, hlv.d
  `0x6c00_4073` (plus rd at bits 11..7, rs1 at 19..15); hsv.b/h/w/d funct7 `0x31/0x33/0x35/0x37`,
  funct3 4, rd 0; hfence.vvma funct7 `0x11`, hfence.gvma funct7 `0x31`, funct3 0, rd 0.
- `csr_read` / `csr_write` stay the raw machine view: the address names the real CSR, with no
  privilege check and no VS redirection (tests use them to set state). Checks and redirection
  apply to CSR instructions only.

## CSRs
New: hstatus 0x600, hedeleg 0x602, hideleg 0x603, hie 0x604, hcounteren 0x606, hgeie 0x607,
henvcfg 0x60A, htval 0x643, hip 0x644, hvip 0x645, htinst 0x64A, hgatp 0x680, hgeip 0xE12 (read
only), vsstatus 0x200, vsie 0x204, vstvec 0x205, vsscratch 0x240, vsepc 0x241, vscause 0x242,
vstval 0x243, vsip 0x244, vsatp 0x280, mtinst 0x34A, mtval2 0x34B. misa gets H (bit 7). GEILEN = 0.
- hstatus writable: VTSR (22), VTW (21), VTVM (20), HU (9), SPVP (8), SPV (7), GVA (6); VSXL
  (33..32) reads 2; the rest 0. mstatus additionally writable: MPV (39), GVA (38).
- medeleg additionally writable: 10 (ecall from VS), 20, 21, 22, 23. hedeleg writable: 0..8, 12, 13,
  15 (never 9, 10, 11, 20..23). hideleg writable: 2, 6, 10. mideleg bits 2, 6, 10, 12 read 1 always.
- hvip writable: 2, 6, 10. hip bits 2, 6, 10 = hvip's (only hip.VSSIP is writable, as hvip bit 2);
  hip bit 12 = 0. hie writable: 2, 6, 10, 12. mip bits 2, 6, 10 read hip's; mip.VSSIP is writable
  (the same bit); mie bits 2, 6, 10, 12 are hie's. sip and sie never show bits 2, 6, 10, 12.
- vsstatus: same writable bits and fixed UXL as sstatus. vstvec, vsscratch, vsepc (bit 0 reads 0),
  vscause, vstval: plain. vsatp: like satp (modes 0 and 8; a write with another mode is ignored).
  vsip/vsie as VS sees them: bit 1 = hip/hie bit 2, bit 5 = bit 6, bit 9 = bit 10, each only when
  that bit is set in hideleg (else reads 0, writes ignored); vsip bit 1 writes hvip bit 2.
- hgatp: MODE (63..60) 0 or 8 (Sv39x4), VMID (57..44) reads 0, PPN (43..0) with bits 1..0 reading
  0; a write with another MODE is ignored. htval, htinst, mtval2, mtinst: plain storage (traps
  write htinst/mtinst as 0). hcounteren, henvcfg: plain storage.
- Access from CSR instructions: H and VS CSRs (0x2xx, 0x6xx, 0xExx above) are HS-level: legal in
  M and HS; from U (virt false) illegal instruction; from VS or VU virtual instruction. When
  virt: the S CSRs 0x100, 0x104, 0x105, 0x140, 0x141, 0x142, 0x143, 0x144, 0x180 act on vsstatus,
  vsie, vstvec, vsscratch, vsepc, vscause, vstval, vsip, vsatp; from VU any S-level CSR is a
  virtual instruction; satp (vsatp) from VS with hstatus.VTVM is a virtual instruction. M-level
  CSRs from VS or VU are illegal instructions. Counter CSRs from VS/VU: allowed only if both
  mcounteren and hcounteren allow (VU also scounteren); if mcounteren allows but hcounteren does
  not, virtual instruction.

## Two-stage translation (when virt, or for HLV/HSV)
- `Cpu::translate(bus, vaddr, access)` does the full two-stage translation when `virt` is set
  (as the current mode, VS or VU), and the old one-stage walk otherwise.
- VS-stage: vsatp mode 0 means `gpa = gva`; mode 8 is an Sv39 walk exactly like today's (bits
  63..38 equal, hardware A/D, superpage alignment, reserved bits), but every page-table address is
  a GPA translated by the G-stage first. U bit and SUM use the VS view (VU needs U; VS needs !U
  or SUM from vsstatus for loads and stores). MXR: vsstatus.MXR or mstatus.MXR. A VS-stage fault
  is an ordinary page fault (12, 13, 15) with tval = gva.
- G-stage: hgatp mode 0 means `pa = gpa`; mode 8 is Sv39x4: gpa bits 63..41 must be zero; root
  table 16 KiB at PPN << 12, top index gpa[40..30] (11 bits), then 9-bit levels as Sv39. Every
  G-stage access is a user access: a leaf without U faults. MXR: mstatus.MXR only. Hardware A/D
  as today. Superpage alignment and reserved bits as Sv39.
- Implicit reads of VS-stage page-table entries are G-stage loads (R, or X with mstatus.MXR).
  When the VS-stage must set A or D, that G-stage translation must also allow a store (W).
- Any G-stage failure (also a bus error reading a G-stage PTE, or gpa too wide) is the guest-page
  fault of the original access type (fetch 20, load 21, store/AMO 23) with `gva` = the original
  virtual address and `gpa` = the address that failed: the final gpa, or the VS page-table entry's
  gpa for an implicit access.
- HLVX needs X (not R) at both stages and faults as a load. HLV/HSV translate as if virt with
  mode VS when hstatus.SPVP = 1 else VU; they are legal in M and HS, in U only with hstatus.HU, and
  a virtual instruction when virt. HLV/HSV misaligned: byte-wise like plain loads/stores.
- HFENCE.VVMA / HFENCE.GVMA: legal in M and HS (GVMA in HS with mstatus.TVM is illegal),
  virtual instruction when virt, illegal in U. They (and SFENCE.VMA, and writes to vsatp, hgatp,
  satp, and every change of `virt`) must leave the fetch translation cache correct.

## Traps, interrupts, returns
- Exception code c from privilege p: if p != M and medeleg[c]: if virt and hedeleg[c] the trap
  goes to VS (vsepc, vscause, vstval, vsstatus SPP/SPIE/SIE, pc from vstvec, `virt` stays true);
  otherwise to HS (sepc, scause, stval; htval = gpa >> 2 for guest-page faults else 0; htinst = 0;
  hstatus.SPV = old virt; if old virt, hstatus.SPVP = 1 if p was S else 0; hstatus.GVA = whether
  the trap value is a guest virtual address; then virt = false). Otherwise to M (mepc, mcause,
  mtval; mtval2 = gpa >> 2 for guest-page faults else 0; mtinst = 0; mstatus.MPV = old virt,
  mstatus.GVA as above; virt = false). The trap value is a guest virtual address when the trap
  came from virt or from HLV/HSV and the cause is 0, 1, 4, 5, 6, 7, 12, 13, 15, 20, 21 or 23.
- Interrupt priority: MEI 11, MSI 3, MTI 7, SEI 9, SSI 1, STI 5, SGEI 12, VSEI 10, VSSI 2, VSTI 6.
  Codes 2, 6, 10 (always in mideleg) go to VS when hideleg has them: taken only while virt, and in
  VS only with vsstatus.SIE (always in VU); the cause in vscause is the code minus 1 (1, 5, 9) with
  bit 63 set; vstvec vectoring uses that code. Without hideleg they go to HS like S interrupts.
  HS-level interrupts are always enabled while virt.
- MRET: mode = MPP, virt = MPV if MPP != M (else false), MPV = 0. SRET from HS: mode = SPP, virt
  = hstatus.SPV, SPV = 0. SRET from VS: uses vsstatus (mode = its SPP, virt stays true); with
  hstatus.VTSR it is a virtual instruction. SRET from VU: virtual instruction.
- WFI: from VU a virtual instruction when mstatus.TW = 0 (illegal when TW = 1); from VS a virtual
  instruction when VTW = 1 and TW = 0. SFENCE.VMA from VS with VTVM, or from VU: virtual
  instruction. An H instruction from virt: virtual instruction.

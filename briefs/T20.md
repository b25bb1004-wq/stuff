## Why

## Public API (exact)
```rust
pub mod rng {
    pub struct ChaChaRng;                       // ChaCha20 block function as a stream
    impl ChaChaRng {
        pub fn from_seed(seed: [u8; 32]) -> ChaChaRng;   // key = seed, nonce = 0, counter from 0
        pub fn fill(&mut self, out: &mut [u8]);           // keystream bytes in order, no gaps
        pub fn next_u64(&mut self) -> u64;                // next 8 keystream bytes, little endian
        pub fn below(&mut self, n: u64) -> u64;           // uniform in 0..n (n > 0), rejection sampling
        pub fn reseed(&mut self, extra: &[u8]);           // key = HKDF(salt = old key, ikm = extra)
    }
}
pub mod sealed {
    pub const OVERHEAD: usize = 32 + 16;        // ephemeral public key + Poly1305 tag
    /// Encrypt `msg` to `recipient`. `eph_secret` is a fresh random 32-byte value from the caller.
    pub fn seal(recipient: &[u8; 32], eph_secret: &[u8; 32], msg: &[u8]) -> Vec<u8>;
    pub fn open(recipient_secret: &[u8; 32], sealed: &[u8]) -> Result<Vec<u8>, crate::aead::Error>;
}
```
## Behaviour
- `ChaChaRng` output is exactly the RFC 8439 ChaCha20 keystream for (key = seed, nonce = 12 zero
  bytes, counter 0, 1, 2, ...). `fill` and `next_u64` share one stream: the byte order does not
  depend on how the calls are split. `below` never returns n or more and has no modulo bias.
- `sealed::seal`: `eph_pub = x25519::public_key(eph_secret)`; `shared = x25519::shared_secret(eph_secret, recipient)`;
  `key = hkdf::expand(hkdf::extract(eph_pub || recipient, shared), "strata sealed v1", 32)`;
  output `eph_pub || aead::seal(key, nonce = 12 zero bytes, aad = eph_pub || recipient, msg)`.
  A zero nonce is safe because every key is used once. `open` reverses it and returns the AEAD
  error for any change to any byte, a wrong recipient, or input shorter than `OVERHEAD`.
  An all-zero shared secret (low-order point) is an error, never a key.

## Tests required
- RNG known answers: the RFC 8439 section 2.4.2 / A.1 keystream blocks (seed = their key, check
  the first 128 bytes against vectors written in the test); same bytes whether read by one
  `fill(128)`, by 128 `fill(1)` calls, or by 16 `next_u64` calls.
- `below`: for n in {1, 2, 3, 7, 1000, 2^63 + 1}, 10 000 draws all < n; a chi-square check for
  n = 6 over 60 000 draws within a loose bound.
- Sealed box: open(seal(x)) == x for random sizes 0..=4096 (`forall`, 300 cases); flipping any
  single byte of a sealed message (every position, for a 50-byte message) makes `open` fail; a
  wrong recipient secret fails; low-order public keys (all zero, and the point of order 8 from
  RFC 7748 section 6.1's list) make `seal` produce a box that `open` rejects, or return an error.

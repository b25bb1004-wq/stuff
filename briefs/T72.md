## Design (fixed by the leader)
- `Cargo.toml`: `crate-type = ["cdylib", "rlib"]`. Depending on `neon` brings its wasm exports (Titan session,
  `logos_run`, `neon_alloc`/`neon_free`/`neon_last_*`) into `athena.wasm`; reuse them, do not duplicate them.
- `src/service.rs` (all targets), plain Rust, host-tested:
  - `pub fn check(src: &str) -> Vec<Diagnostic>` with `pub struct Diagnostic { pub line: u32, pub col: u32,
    pub end_line: u32, pub end_col: u32, pub message: String }` (1-based; parse then check; empty when clean).
  - `pub fn highlight(src: &str) -> Vec<(usize, usize, Style)>`: byte ranges of runs of one calliope `Style`
    (`highlight("x.logos", src)` merged into runs), covering the whole text in order.
  - `pub fn run_tests(src: &str, fuel: u64) -> Result<Vec<TestResult>, Vec<Diagnostic>>` with
    `pub struct TestResult { pub name: String, pub passed: bool, pub detail: String }`: every unit test, then every
    property (`run_prop`), in source order within each group.
- `src/wasm.rs` (`cfg(target_arch = "wasm32")`), same ABI style as neon (result in neon's last buffer, return len):
  `athena_check(ptr, len) -> len`: one line per diagnostic `line:col:end_line:end_col:message`;
  `athena_highlight(ptr, len) -> len`: one line per run `start len class` (class = the `Style` variant in lower case);
  `athena_test(ptr, len, fuel: u64) -> len`: `PASS name` / `FAIL name: detail` lines, or `error: ...` lines.
  If writing neon's last buffer from another crate is not possible through neon's public API, keep a last buffer
  in athena with `athena_last_ptr`/`athena_last_len` and say so in the report.
- `web/index.html`, `web/athena.js`, `web/style.css`: the Athena layout of `docs/FRONT.md`.
  - Files live in `localStorage` key `athena.files.v1` (a JSON object path -> text), every access in try/catch;
    when empty or unavailable, seed `main.logos` (prints with a loop), `math.logos` (functions + 2 unit tests +
    1 property, all passing) and `broken.logos` (one type error). File tree: open, new, rename, delete, with inline
    controls; **never** `alert`, `confirm` or `prompt`.
  - Editor as `docs/FRONT.md` says (textarea over highlighted pre, gutter, Tab, Ctrl/Cmd+Enter run, Ctrl/Cmd+S
    save). Re-highlight and re-check 300 ms after typing stops; diagnostics underlined and listed; clicking one
    moves the caret.
  - Run: `logos_run` on the open file into `Output`. Test: `athena_test` into `Tests` with a pass/fail count.
  - Terminal tab: the neon Titan session, booted on first open (fetch `titan.elf`), same pump loop as `neon.js`.
  - 360 px: the tab strip layout from `docs/FRONT.md`; reduced motion and both themes honoured.
- `src/pack.rs` (`cfg(not(target_arch = "wasm32"))`): `pub fn pack(out: &Path) -> Result<(), String>`: builds
  `athena` for `wasm32-unknown-unknown --release` and the titan kernel (nested cargo with own target dirs, as
  neon's pack does), writes `out/{index.html, athena.js, style.css, athena.wasm, titan.elf}`.
  `examples/pack.rs` packs into `target/athena-web` and prints the path.

## Tests
- `tests/service.rs`: `check` on clean source is empty, on a type error gives the right line and col, on a syntax
  error gives line 1..; `highlight` runs are contiguous, cover every byte, and a keyword, a string and a comment get
  their styles; `run_tests` on the seeded `math.logos` text gives 3 passes in order, a failing test gives
  `passed: false` with detail, a source with a type error gives `Err`; random byte strings never panic any function.
- `tests/wasm_build.rs`: `pack` into `CARGO_TARGET_TMPDIR`; parse `athena.wasm` (copy neon's small reader) and
  assert the three athena exports plus neon's `titan_boot`, `titan_pump`, `logos_run`, `neon_alloc` exist and imports
  are empty or `env` only; all five files exist; `index.html` references only local files; no `alert(`, `confirm(`
  or `prompt(` in `athena.js`; `style.css` defines every token name from `docs/FRONT.md`.

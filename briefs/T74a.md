## Design (fixed by the leader)
- elysium: move the interpreter loop's state (`frames`, register stack, fuel used) into
  `pub struct Session` so it can stop and continue. `run`/`call` become: create a session, resume with no pause
  condition. New public API in `debug.rs`:
  - `Vm::start(&mut self, func: u32, args: &[Value], limits: Limits) -> Result<Session, Trap>`
  - `Session::resume(&mut self, vm: &mut Vm, host: &mut dyn Host, until: &dyn Fn(&Position) -> bool,
    max_steps: u64) -> Event` where `Event` is `Paused(Position)` (the `until` predicate returned true before
    executing the op at that position), `Budget` (`max_steps` ops ran), `Done(Value)`, `Trapped(Trap)`.
    `until` is not checked on the very first op of a resume, so resuming from a breakpoint moves on.
  - `pub struct Position { pub func: u32, pub pc: u32, pub depth: u32 }`.
  - `Session::frames(&self) -> Vec<FrameView>`: innermost last; `FrameView { func, pc, regs: Vec<Value> }`
    (the frame's registers as values; heap references stay `Value`s, render them with the heap).

## Tests
- elysium `tests/debug.rs`: for random generated programs (use the crate's existing `testgen` if public, else small
  hand-written modules), running through `start` + `resume` with a never-true predicate gives exactly the same value,
  trap and fuel as `run`; pausing on every op and resuming each time gives the same final result; frames at a pause
  inside a nested call show 2 frames with the right funcs.

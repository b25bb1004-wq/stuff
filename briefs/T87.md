# T87 apps (crates/site): app kit, launcher, and a standalone installable app per system with a live demo
Worker: hydrogen-high (agy). Budget: one run, at most 150 minutes. First read `briefs/_RULES.md`, `docs/APPS.md`
(all; the "App conventions" are part of this brief), `docs/FRONT.md` (tokens and rules), then
`crates/site/src/{lib.rs,pack.rs,wasm.rs}`, `crates/site/src/demos/mod.rs`, `crates/site/web/{site.js,systems.js}`,
`crates/site/tests/wasm_build.rs`, `crates/athena/src/icons.rs` (how athena draws its icons with pigment) and
`crates/athena/web/sw.js`. Read nothing else.
**May touch:** `crates/site/` only. Host-only path dep allowed: `pigment`. Zero external crates; no `alert`,
`confirm`, `prompt`; no request to any other host.

## What to build
- `apps/_kit/kit.js` + `kit.css`: `Kit.mount({ id, name, about, help })` draws the 40 px title bar (icon, `Monolith
  <Name>`, Install button shown on `beforeinstallprompt` and hidden in standalone mode, theme toggle, About dialog
  with the paragraph, source folder and the tool's usage text), handles window-controls-overlay
  (`env(titlebar-area-*)`), registers `./sw.js`, and gives `Kit.wasm()` (loads `../site.wasm` once, returns the
  same demo call helpers `site.js` uses), `Kit.store(key)` (localStorage under `monolith.<id>.*`, wrapped in
  try/catch), `Kit.download(name, text)` and `Kit.pickFile()` for Export and Import.
- Generic demo app (`apps/_kit/demo-app.js`): full-window layout: left an input editor (monospace, Tab inserts 4
  spaces, Ctrl/Cmd+Enter runs) with an Examples menu, right the output (text, or a canvas for `Pixels`), a Run
  button, a run history list (last 20 runs with time and first line, click restores), input persisted per app,
  Export and Import of the input. Mobile: one column with Input / Output tabs.
- One app per registered demo (the 15 in `demos::all()` plus titan and logos from neon): `apps/<id>/index.html` and a
  tiny `app.js` giving `id`, `name`, `about` (one paragraph from `systems.js`'s line plus one sentence), the tool usage
  text from `docs/APPS.md`'s row, and 3 examples (the demo's default input and two more that show something
  different, at least one an error case). Titan's app is a full-window terminal (reuse site.js's terminal code);
  logos's app is the playground with the three examples it has now.
- `apps/index.html` (`/apps/`): launcher grid of all 25 systems (icon, name, one line); systems without an app yet
  show "coming soon" and are not links. Athena links to `../athena/`.
- Site: each section with an app gets an "Open app" link to `<id>/`; the hero gets "All apps" linking `apps/`.
- `pack`: for each app writes `out/<id>/{index.html, app.js, manifest.webmanifest, sw.js, icon-192.png,
  icon-512.png, icon-maskable-512.png}` and `out/_kit/*`, `out/apps/index.html` (with icons). Icon per
  `docs/APPS.md`: a 5x7 bitmap font you embed (capital letters only) scaled up in `--accent` on `--bg` with a thin
  `--line` ring. `sw.js` per app caches its own files, `../_kit/*` and `../site.wasm` (plus `../titan.elf` for titan)
  under a content-hashed cache name, cache-first, old caches deleted, navigation falls back to its `index.html`.

## Tests

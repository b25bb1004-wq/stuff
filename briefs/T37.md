## Public API (exact, in `mercury::server`)
```rust
pub struct Config { pub addr: String, pub threads: usize, pub limits: crate::Limits,
                    pub read_timeout_ms: u64, pub keep_alive_max: u32, pub max_connections: usize }
impl Default for Config { /* "127.0.0.1:0", 8 threads, Limits::default(), 5000 ms, 100, 1024 */ }
pub type Handler = Box<dyn Fn(&crate::Request) -> crate::Response + Send + Sync>;
pub struct Router;
impl Router {
    pub fn new() -> Router;
    pub fn route(&mut self, method: &str, path: &str, h: Handler);   // exact path, or prefix ending in '/*'
    pub fn static_dir(&mut self, prefix: &str, dir: std::path::PathBuf); // GET and HEAD only
}
pub struct Server;
impl Server {
    pub fn start(cfg: Config, router: Router) -> std::io::Result<Server>;
    pub fn local_addr(&self) -> std::net::SocketAddr;
    pub fn stats(&self) -> ServerStats;
    pub fn stop(self);            // stop accepting, finish in-flight requests, close idle
}                                 // keep-alive connections, join everything; returns in < 2 s
#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub struct ServerStats { pub accepted: u64, pub requests: u64, pub open: u64, pub rejected: u64 }
```
## Behaviour
- One acceptor thread on `std::net::TcpListener`; each connection is a job on a `kairos::pool::Pool`.
  A connection serves requests in order (pipelining works because the parser returns `bytes_used`)
  until `Connection: close`, HTTP/1.0 without keep-alive, `keep_alive_max` requests, a read timeout,
  or a parse error.
- Parse errors answer `400` (or `413` for `HeadTooLarge`/`BodyTooLarge`, `431` for
  `TooManyHeaders`) with `Connection: close`, then close. No route: `404`. Route exists for the
  path but not the method: `405` with an `Allow` header. A handler panic: `500`, connection closed,
  server keeps running.
- Over `max_connections` open: accept and immediately answer `503` and close (count `rejected`).
- Slow clients: a connection that sends less than one byte per `read_timeout_ms` is closed, so a
  slowloris attack holds at most `max_connections` sockets and never a thread forever.
- Static files: path joined under `dir` after percent-decoding; any `..` segment, a NUL byte or an
  absolute path is `404`, never a file outside `dir`. `Content-Type` from the extension (html,
  css, js, json, png, jpg, svg, wasm, txt; otherwise `application/octet-stream`), `HEAD` sends
  headers only, `index.html` for a directory.
- `ServerStats.open` returns to 0 after clients disconnect (no leaked connection jobs).

## Tests required (integration tests with real sockets on 127.0.0.1, port 0)
- Routes, 404, 405 with `Allow`, handler panic gives 500 and the next connection works.
- Keep-alive: 100 requests on one connection; pipelined requests written in one `write` all answered in order.
- Own load tool in the test: 10 000 connections from 32 client threads, each a GET; all get 200,
  then `open == 0` and `accepted == 10_000` within 10 s.
- Slowloris: 50 sockets each sending one byte per second; a normal client still gets answers;
  the slow sockets are closed after the timeout (`read_timeout_ms` set to 300 in the test).
- Static: file served with the right type and length; `..`, `%2e%2e`, absolute and NUL paths give 404.
- `stop()` with 20 idle keep-alive connections and one in-flight slow handler returns within 2 s
  after the handler finishes, and the in-flight request still gets its response.

## Public API (exact; `ws` re-exported as `mercury::ws`)

`stream` handlers return the status code, and the response head carries it with
`Content-Type: application/octet-stream`. A handler that panics ends the stream without a
terminating chunk and closes the connection.

## Behaviour
- **Handshake (RFC 6455 4.2):** GET with `Upgrade: websocket` (any case), `Connection`
  containing the token `upgrade`, `Sec-WebSocket-Version: 13` and a key that is 16 bytes in
  base64 -> `101 Switching Protocols` with `Sec-WebSocket-Accept`. Wrong version -> `426` with
  `Sec-WebSocket-Version: 13`; other bad handshakes -> `400`. A websocket route hit by a plain
  GET -> `400`. The socket leaves the keep-alive loop and is owned by the handler's thread
  (it counts toward `max_connections` until dropped).
- **Frames (RFC 6455 5):** client frames must be masked (else close 1002); RSV bits set,
  unknown opcodes, fragmented or >125-byte control frames, continuation without a start, a new
  data frame inside a fragmented message -> close 1002; invalid UTF-8 in a text message -> close
  1007; a message over the limit (default 16 MiB) -> close 1009. Close codes are sent in a close
  frame and then the socket is closed.
- **Ranges (RFC 9110 14):** static files answer `Accept-Ranges: bytes`. A single range
  `bytes=a-b`, `bytes=a-` or `bytes=-n` -> `206` with `Content-Range: bytes a-b/len` and just
  those bytes (b clamped to len-1); unsatisfiable -> `416` with `Content-Range: bytes */len`;
  several ranges or a malformed header -> `200` with the whole file. HEAD gives the same headers
  without a body.
- **Chunked request bodies** (already parsed by T36) work on every route, within the body limit.

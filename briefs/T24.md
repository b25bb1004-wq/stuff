## What it is
The kernel is assembly text in `crates/flint/kernel/kernel.s`, embedded with `include_str!` and
assembled by `chisel::assemble(src, quartz::machine::RAM_BASE)`. Rust code only builds and runs
it; no kernel logic in Rust.

## Public API (exact)
```rust
pub const KERNEL_SRC: &str;                     // include_str!("../kernel/kernel.s")
pub fn image() -> Result<Vec<u8>, chisel::AsmError>;  // assembled bytes at RAM_BASE
pub fn boot(cfg: quartz::machine::Config) -> Result<quartz::machine::Machine, String>; // loaded, pc at RAM_BASE
pub fn run(steps: u64) -> (quartz::machine::Exit, Vec<u8>);   // boot(Default), run, UART output
```

## Kernel behaviour (exact)
1. Boot in M-mode at RAM_BASE: set sp to a kernel stack, `mtvec` to the trap handler (direct
   mode), print `flint: boot\n` on the UART (poll LSR bit 5 before each THR write).
2. Two tasks, each with its own stack and saved register frame (all 31 regs + pc). Tasks run in
   U-mode (`mstatus.MPP = 0`, `mret`). Task A prints `A0\n`..`A4\n` via syscall; task B prints
   `B0\n`..`B4\n`. Each task busy-loops about 2000 instructions between prints, then exits.
3. Timer: CLINT `mtimecmp = mtime + 5000` and re-armed on each timer interrupt (`mie.MTIE`,
   `mstatus.MPIE`); each timer interrupt saves the running task and switches to the other live one.
4. Syscalls via `ecall` from U-mode, number in a7, args a0..a2, return in a0, `mepc += 4`:
   - 1 `write(ptr, len)`: copy bytes to the UART, return len.
   - 2 `yield()`: switch to the other live task, return 0.
   - 3 `exit(code)`: mark the task dead; when both are dead print `flint: halt\n` and write
     0x5555 to the test finisher (0x0010_0000).
   - any other number returns -1 (all ones) in a0.
5. Any other trap (illegal instruction, access fault, misaligned) prints `flint: panic <mcause
   in hex>\n` and writes `(1 << 16) | 0x3333` to the finisher.

The full transcript is therefore `flint: boot\n`, then the ten task lines interleaved in whatever
order the timer produces (deterministic for a given image), then `flint: halt\n`.

## Tests required (`crates/flint/tests/kernel.rs`)
- `golden_boot`: `run(1_000_000)` gives `Exit::Pass`; the output starts `flint: boot\n`, ends
  `flint: halt\n`, contains each of A0..A4 and B0..B4 exactly once, A lines in order, B lines in
  order, and at least one A line after a B line and one B line after an A line (the timer really
  preempts). Also commit the exact transcript as `tests/golden.txt` and compare byte for byte.
- `deterministic`: two machines stepped 1_000_000 times (`step` until Pass, then stop) give equal
  UART output and equal `mtime`.
- `image_shape`: `image()` is non-empty, under 64 KiB, and `task_a_body` is in `chisel::assemble(..).symbols`.

## Extra check the leader will run
`crates/flint/tests/flint_leader.rs`: the golden properties above, step-count bounds, and
patched images (illegal instruction in task A must give `flint: panic 0x2` and `Exit::Fail(1)`).
To make that patchable, put the label `task_a_body:` at the first instruction of task A's loop
and keep task A's first instruction a 4-byte instruction.

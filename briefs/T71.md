## Design (fixed by the leader)
- `Cargo.toml`: `crate-type = ["cdylib", "rlib"]`.
- `src/session.rs` (all targets): `pub struct Titan` owning a `Machine` (32 MiB RAM, `decode_cache` on) booted from a
  titan kernel ELF with a hades disk holding `/etc/shell` (and `/hello.txt` = `hello`), `a1` = RAM size.
  - `Titan::boot(elf: &[u8]) -> Result<Titan, String>`
  - `fn send(&mut self, line: &str)`: queue `line` + `\n` on the UART.
  - `fn pump(&mut self, max_steps: u64) -> Pump` runs until one of: the output so far ends with `$ ` and no input is
    queued (`Pump::WaitingForInput`), the machine exits (`Pump::Exited(code)`), or `max_steps` (`Pump::Busy`).
    Stopping while the prompt waits means titan sees no time pass, so its 1-tick EOF rule never fires in the page.
  - `fn take_output(&mut self) -> Vec<u8>`.
- `src/playground.rs` (all targets): `pub fn run_logos(src: &str, fuel: u64) -> String`: parse, check, compile, run
  `main`; returns program output, or `error: <line>:<col>: <message>` lines for diagnostics, or a trap message.
- `src/wasm.rs` (`cfg(target_arch = "wasm32")`): `#[no_mangle] pub extern "C"` exports, our own ABI:
  `neon_alloc(len) -> *mut u8`, `neon_free(ptr, len)`, `titan_boot(ptr, len) -> i32` (0 ok, else an error string is
  ready via `neon_last_len`/`neon_last_ptr`), `titan_send(ptr, len)`, `titan_pump(max_steps: u64) -> i32`
  (0 waiting, 1 busy, 2 + code exited), `titan_output(out_ptr_ptr) -> len` (or the last-buffer pair, your choice,
  documented in the README), `logos_run(ptr, len, fuel: u64) -> len` with the result in the last buffer. One global
  session in a `static` cell; no `unsafe` beyond the pointer/slice conversions, each with a SAFETY comment.
- `web/index.html`, `web/neon.js`, `web/style.css`: plain HTML/CSS/JS. `neon.js` loads `neon.wasm` with
  `WebAssembly.instantiateStreaming` (fallback `instantiate`), fetches `titan.elf`, boots, and drives `titan_pump`
  from `requestAnimationFrame` (about 2 M steps per frame) while busy; a terminal pane shows output and an input line
  sends what the user types on Enter. A Logos pane: textarea, a Run button, an output box, three example programs
  in a select (hello, loop with arithmetic, an error). Works at 360 px wide. No external requests besides the
  page's own files.
- `src/pack.rs` (`cfg(not(target_arch = "wasm32"))`): `pub fn pack(out: &Path) -> Result<(), String>` builds
  `neon` for `wasm32-unknown-unknown --release` and the titan kernel for riscv64 (nested cargo with their own target
  dirs, like titan's tests), then writes `out/{index.html, neon.js, style.css, neon.wasm, titan.elf}`.
  `examples/pack.rs` calls it with `target/neon-web` and prints the path.

## Tests
- `tests/session.rs` (host): boot titan through `Titan`, feed the same 14-line session as titan's
  `shell_session_transcript_and_disk_persistence`, line by line, calling `pump` until `WaitingForInput` before each
  `send`; the shell part of the output must equal the titan test's expected transcript. Also: nothing is lost when
  `pump` stops on `Busy` many times (small `max_steps`), and a session with no input waits (does not exit) after
  10 pumps.
- `tests/playground.rs`: the three examples give the expected output; a syntax error gives `error: 1:..`; an endless
  loop stops at the fuel limit with a message; random byte strings never panic.
- `tests/wasm_build.rs`: calls `pack` into `CARGO_TARGET_TMPDIR`, then parses `neon.wasm` (write the small reader in
  the test: magic, version, sections, the export section) and asserts every export above is present and the import
  section is empty or imports nothing outside module `env`; all five files exist and `index.html` references only
  local files.

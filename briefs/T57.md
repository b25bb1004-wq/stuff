## Public API (exact, `krypton::exec`, feature `std`)
```rust
pub struct Shell { /* vars, exported set, functions, positional, cwd, last status, jobs, options */ }
impl Shell {
    pub fn new() -> Shell;                         // imports the process environment as exported vars
    pub fn set_cwd(&mut self, dir: std::path::PathBuf);
    /// Run a whole script; output goes to the given writers (builtins write here; external
    /// commands get pipes that are copied here). Returns the exit status of the last command.
    pub fn run(&mut self, src: &str, stdin: &mut dyn std::io::Read,
               stdout: &mut dyn std::io::Write, stderr: &mut dyn std::io::Write) -> i32;
    pub fn status(&self) -> i32;
    pub fn exited(&self) -> Option<i32>;           // Some after the `exit` builtin
}
```
`Shell` implements `krypton::Env` (command substitution runs the script in a subshell copy and
captures its stdout).

## Behaviour (POSIX XCU 2.9, 2.14)
- Simple commands: assignments only -> set variables; with a command name: function, then builtin,
  then external program searched in `PATH` (Windows: also `PATHEXT`; split on `;` there, `:` on
  Linux). Assignments before a command apply to that command only. Status 127 not found, 126
  not executable, 128+n killed by signal n (Linux).
- Pipelines: every stage runs concurrently (externals as processes connected by OS pipes;
  builtins and functions on threads with in-memory pipes); status of the last stage, `!` negates.
- `&&` `||` `;` `&`, `if`, `while`, `until`, `for`, `case` (with `glob_match`), `{ }`, `( )`
  (a subshell: a copy of the shell state; changes do not leak back), functions with positional
  parameters, `return`, `break n`, `continue n`.
- Redirects `< > >> <> >| n>&m n<&m n>&-` and here-docs (expanded unless quoted), applied left
  to right, for builtins and externals alike; `>` fails if the file can't be created (status 1,
  message on stderr).
- Builtins: `: true false echo printf cd pwd exit export unset set shift read test [ return break
  continue eval . wait jobs type local`. `echo` takes no options except `-n`; `printf` supports
  `%s %d %i %x %o %c %b %%`, widths, `-` flag, and reuses the format for extra arguments; `test`
  supports POSIX unary file/string tests, `= != -eq -ne -lt -le -gt -ge`, `!`, `-a -o`, parentheses.
  `set -e`, `set -u`, `set -x` (trace to stderr with `+ `), `set --`.
- `&` runs the and-or list in the background (a thread for builtins, a child for externals);
  `$!`, `jobs` lists `[n] Running|Done  text`, `wait [n]` waits and returns that status.
  Terminal job control (Ctrl-Z, `fg`, `bg`, process groups) is out of scope; say so in `krypton --help`.
- Binary: `krypton -c SCRIPT [ARGS]`, `krypton FILE [ARGS]`, or interactive when stdin is a terminal
  or no arguments: prompt `$ `, continuation prompt `> ` while `parse` says `incomplete`.

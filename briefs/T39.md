## Public API (all re-exported at the crate root, exact)
```rust
pub const PAGE: usize = 4096;
pub const USABLE: usize = 4092;          // bytes 4092..4096 of every page are its CRC-32
pub type Page = [u8; PAGE];
#[derive(Debug, Clone, PartialEq, Eq)] #[non_exhaustive]
pub enum Error { Io, Corrupt, TooLarge, Busy, Misuse }   // T41 adds the SQL ones later
pub trait Storage {
    fn len(&mut self) -> Result<u64, Error>;
    fn read_at(&mut self, off: u64, buf: &mut [u8]) -> Result<(), Error>; // Io if past the end
    fn write_at(&mut self, off: u64, data: &[u8]) -> Result<(), Error>;   // grows, zero gap
    fn set_len(&mut self, n: u64) -> Result<(), Error>;
    fn sync(&mut self) -> Result<(), Error>;
}
pub struct MemStorage; // new(), Default, from_bytes(Vec<u8>), bytes(&self) -> &[u8]
pub struct FileStorage; // open(path: &std::path::Path) -> Result<Self, Error>, creates if missing
pub struct CrashStorage<S>; // your crash simulator for your own tests (IRIDIUM.md section 1)
#[derive(Debug, Clone, Copy, PartialEq, Eq)] pub struct Snapshot(/* private */);
pub struct Pager<S: Storage>;
impl<S: Storage> Pager<S> {
    pub fn open(main: S, log: S) -> Result<Self, Error>;
    pub fn page_count(&self) -> u64;
    pub fn root(&self) -> u64;
    pub fn begin(&mut self) -> Result<(), Error>;
    pub fn read(&mut self, n: u64) -> Result<Page, Error>;
    pub fn write(&mut self, n: u64, page: &Page) -> Result<(), Error>;
    pub fn alloc(&mut self) -> Result<u64, Error>;
    pub fn free(&mut self, n: u64) -> Result<(), Error>;
    pub fn set_root(&mut self, root: u64) -> Result<(), Error>;
    pub fn commit(&mut self) -> Result<(), Error>;
    pub fn rollback(&mut self);
    pub fn snapshot(&mut self) -> Snapshot;
    pub fn read_snapshot(&mut self, snap: Snapshot, n: u64) -> Result<Page, Error>;
    pub fn release(&mut self, snap: Snapshot);
    pub fn checkpoint(&mut self) -> Result<bool, Error>;
    pub fn log_frames(&self) -> u64;
    pub fn close(self) -> Result<(S, S), Error>;
    pub fn into_storage(self) -> (S, S);
}
```

## Rules (beyond the doc)
- `open` on an empty main file writes page 0 (page count 1, free head 0, root 0, change counter
  0) to it and syncs it. A log with an invalid or missing header is reset as the doc says (salt 1).
  A main file whose page 0 has a bad magic or CRC is `Corrupt`. `open` never writes the main file
  otherwise.
- `page_count`, `root`, `read` show the open write transaction's view if one is open, else the
  latest commit. `read(0)` returns page 0. `read(n)` for `n >= page_count` is `Misuse`; a page
  whose stored CRC is wrong (and has no newer log copy) is `Corrupt`.
- `write`, `alloc`, `free`, `set_root`, `commit` outside a transaction are `Misuse`; `begin`
  inside one is `Busy`. `write` and `free` of page 0 or of `n >= page_count` are `Misuse`; freeing
  the same page twice in one transaction is `Misuse`. `write` ignores the caller's bytes
  4092..4096 and stores the page's CRC there. Nothing reaches storage before `commit`.
- `alloc` pops the free list head, else grows the page count; the new page reads as zeros
  (with a valid CRC). `free(n)` makes `n` a free page (byte 0 = 5, next at byte 16 = the old head,
  other bytes zero) and the new head.
- Every commit writes page 0 (change counter + 1) plus every page the transaction wrote, freed or
  allocated, as log frames (the commit frame last), then syncs the log. Then, if the log holds
  more than 1000 frames and no snapshot is held, it checkpoints. `rollback` drops everything.
- `snapshot` marks the current kept log frames; `read_snapshot` reads the page as of that mark;
  `read_snapshot` after `release` is `Misuse`. `checkpoint` returns `Ok(false)` and does nothing
  while any snapshot is held, else checkpoints (doc section 3) and returns `Ok(true)`; afterwards
  `log_frames()` is 0.
- `close` rolls back an open transaction, checkpoints (ignoring held snapshots) and returns the
  storages. `into_storage` and `Drop` do no I/O (that is how tests simulate a kill).
- Any `Err` from storage is returned as is; after one, the pager may refuse further work, but
  reopening the storages must always recover per the doc.

## Tests required
Model-based: random transactions (alloc, write, free, set_root, commit or rollback, checkpoint)
against a `BTreeMap` model, reopened after every step. Crash at every storage operation with
`CrashStorage` (sector loss as the doc says), reopened: each committed transaction present, the
in-flight one all or nothing. Snapshots, free list order, misuse errors, hostile log and main
bytes (never panic), `FileStorage` round trip in a temp directory.

## Extra check the leader will run
`crates/iridium/tests/pager_leader.rs`: its own disk with per-sector loss of unsynced writes, a
crash at every storage operation of several workloads (three loss patterns each, plus a second
crash during the recovery's checkpoint), byte-exact log and page formats parsed by its own reader
(magic, salts, commit field, CRCs, page 0 fields, free pages), frames after the last commit and
wrong-salt frames ignored, main file untouched by commits, snapshots, auto-checkpoint, misuse
errors, byte flips and truncation of the log (state is always some earlier commit), corrupt main
pages, `FileStorage`.

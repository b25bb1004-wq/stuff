## Why
The kernels (T24, T25), sinter's back end (T29) and mantle's process loader (T26) exchange RV64
executables as ELF. Our files must be readable by LLVM's tools, and we must read LLD's files.

## Public API (`chisel::elf`, exact)
```rust
pub const PF_X: u32 = 1;
pub const PF_W: u32 = 2;
pub const PF_R: u32 = 4;
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Segment { pub vaddr: u64, pub flags: u32, pub data: Vec<u8>, pub mem_size: u64 }
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Image { pub entry: u64, pub segments: Vec<Segment>, pub symbols: Vec<(String, u64)> }
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum ElfError { Truncated, BadMagic, Unsupported(String), BadSegment(String) }
pub fn write(img: &Image) -> Vec<u8>;
pub fn read(bytes: &[u8]) -> Result<Image, ElfError>;
pub fn load(img: &Image, m: &mut quartz::machine::Machine) -> Result<(), quartz::Fault>;
```

## write (exact fields; offsets of tables and padding are yours)
All little-endian. `write` may panic on a caller error: `mem_size < data.len()`, two segments
overlapping in memory, `vaddr + mem_size` overflowing, an empty symbol name or one containing NUL.
- ELF header (64 bytes): `7f 45 4c 46`, class 2, data 1, version 1, OS ABI 0, ABI version 0, zero
  padding; `e_type` 2 (ET_EXEC), `e_machine` 243 (RISC-V), `e_version` 1, `e_entry`, `e_phoff` 64,
  `e_shoff` (section headers), `e_flags` 1 (RVC, soft-float ABI), `e_ehsize` 64, `e_phentsize` 56,
  `e_phnum` = segment count, `e_shentsize` 64, `e_shnum` 4, `e_shstrndx` = index of `.shstrtab`.
- One PT_LOAD (type 1) per segment, in the given order: `p_flags` = flags, `p_offset` with
  `p_offset % 4096 == vaddr % 4096`, `p_vaddr` = `p_paddr` = vaddr, `p_filesz` = data length,
  `p_memsz` = mem_size, `p_align` 4096. The file holds `data` at `p_offset`.
- Sections, always these 4 in this order: null; `.shstrtab` (type 3); `.symtab` (type 2,
  `sh_entsize` 24, `sh_addralign` 8, `sh_link` = index of `.strtab`, `sh_info` 1); `.strtab`
  (type 3). Section names are looked up in `.shstrtab` by `sh_name`.
- `.symtab`: entry 0 all zero, then one entry per symbol in order: `st_name` (offset in `.strtab`,
  which starts with a NUL), `st_info` 0x10 (global, no type), `st_other` 0, `st_shndx` 0xfff1
  (absolute), `st_value` = address, `st_size` 0.
- No waste: file length at most `64 + 56*n + 4096*(n+1) + sum(data) + 256 + 24*(k+1) + sum(name+1) + 32`
  for `n` segments and `k` symbols.

## read
- Accepts any little-endian ELF64 RISC-V executable, including LLD's
  (`tests/fixtures/elf/prog.elf`). Errors, checked in this order: fewer than 64 bytes `Truncated`;
  wrong magic `BadMagic`; class not 2, data not 1, version not 1, `e_type` not 2, `e_machine` not 243
  or `e_phentsize` not 56: `Unsupported(..)`; any program header, segment bytes, section header,
  symbol table or string out of the file: `Truncated`; `p_filesz > p_memsz`, `vaddr + memsz`
  overflow, or two PT_LOAD ranges overlapping in memory: `BadSegment(..)`.
- `segments`: the PT_LOAD headers in program-header order (others ignored), data = the file bytes.
- `symbols`: from the first SHT_SYMTAB section (names through its `sh_link` string table), every
  entry with a non-empty name and type NOTYPE, FUNC or OBJECT (`st_info & 0xf` in 0..=2), in table
  order, value = `st_value`. No symbol table: empty list. So `read(&write(img)) == Ok(img)`.

## load
For each segment in order: `m.load(vaddr, data)`, then zero `[vaddr + data.len(), vaddr + mem_size)`
(RAM may hold old bytes), then set `m.cpu.pc = entry`. Return the first `Fault`.

## Design (fixed by the leader)
- **One multicall user binary** `src/bin/userland.rs`, `no_std`/`no_main` on `target_os = "none"` exactly like
  `kernel.rs` (a stub `main` on the host). It dispatches on `argv[0]`: `sh`, `ls`, `cat`, `echo`, `mkdir`, `rm`, `ps`.
  Runtime: `_start` takes `a0 = argc`, `a1 = argv` (array of pointers to NUL-terminated strings), a bump
  `#[global_allocator]` over `sbrk`, a panic handler that writes `panic\n` to fd 2 and exits 101, thin `syscall` wrappers.
  Linked at the user base with `user.ld` via `cargo:rustc-link-arg-bin=userland=-T...` (kernel keeps its own `-T`;
  switch the kernel to `rustc-link-arg-bin=kernel=` so each bin gets only its own script).
- **build.rs**, when `TARGET` starts with `riscv64`: run a nested
  `cargo build --release -p titan --bin userland --target riscv64gc-unknown-none-elf` with
  `CARGO_TARGET_DIR=$OUT_DIR/userland-target` and an env var guard (e.g. `TITAN_NESTED=1`, skip the nested build when it
  is set) so it does not recurse; copy the ELF to `$OUT_DIR/userland.elf`. Host builds do nothing new.
- `progs::find_builtin` maps all seven names to `USERLAND_ELF`. The asm programs stay as they are.
- **spawn passes argv**: copy up to 16 strings (each at most 255 bytes, 4 KiB total, else -1) from the parent onto the
  child's user stack (strings, then the 8-byte-aligned pointer array, then NULL); child starts with `a0 = argc`,
  `a1 = argv`. `argc == 0` gives the child `argv = [name]`.
- **stdin**: `read(0, ..)` polls the UART receiver: returns the bytes waiting (at least 1, blocking by yielding while
  empty), and 0 (EOF) once the input is empty and the machine's UART input queue is closed/exhausted. Pick the simplest
  EOF rule that works with `Machine::uart_input` given before boot, and write it in TITAN.md.
- **Redirection**: `spawn` gets `a4 = stdin_fd`, `a5 = stdout_fd` (`-1` = console). A file fd given there is copied into
  the child's fd 0 / fd 1 (same path and flags, its own offset starting at the parent's). `read`/`write` on fd 0/1 use the
  file when one is installed, the UART otherwise. Old callers pass garbage in a4/a5: treat any value outside 3..=15 as
  console, so the asm programs keep working unchanged.
- **sh**: reads lines from fd 0, prints the prompt `$ ` before each line, parses with `krypton::parse`, expands with
  `krypton::expand` and a small `Env` (variables, `$?`). Supports: simple commands with args, `;`, `&&`, `||`, `>`,
  `>>` (open with create|write and seek to end: add an append flag `16` to open), `<`, `VAR=value`, builtins `exit [n]`,
  `echo` may be the program. No pipes, no `cd` (absolute paths only): an unsupported construct prints
  `sh: unsupported` and sets `$?` to 2. Unknown command prints `sh: <name>: not found`, `$?` 127. EOF exits 0.
- **Utilities**: `ls [dir]` (readdir, one name per line), `cat file...`, `echo args...` (joined by one space),
  `mkdir dir`, `rm path` (unlink), `ps` (the ps syscall output). Errors print `<prog>: <path>: error <code>` to fd 2 and
  exit 1.
- **init**: after fsdemo, and only when `open("/etc/shell", 1)` succeeds (close it), spawn `sh` and wait; print
  `init: sh exited <n>` before the ps line. Disks without `/etc/shell` give exactly the T27 transcript.

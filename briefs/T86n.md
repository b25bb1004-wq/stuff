# T86n tool (crates/neon): the `titan` command-line tool
Worker: hydrogen-high (agy). Budget: one run, at most 90 minutes. First read `briefs/_RULES.md`, then `docs/APPS.md`
(the "Tool conventions" section and the `titan` row; those rules are part of this brief), then only the public
items of `crates/neon/src/lib.rs` and the modules they point to that you call. Read nothing else.
**May touch:** `crates/neon/src/bin/titan.rs`, `crates/neon/tests/cli_titan.rs`, `crates/neon/Cargo.toml`
(a `[[bin]]` entry or a path dependency already in the workspace, never one that creates a cycle) only. Do not
change library code; if a subcommand needs something the library does not offer, leave it out and say so. Zero
external crates. Your gate is `bash tools/check.sh neon`; you can only run commands for `neon`.

## Tool
- `titan`: `boot [--disk IMG] [--script FILE]`: boots the titan kernel on Silicon through `neon::session::Titan` (the kernel ELF: `--kernel PATH`, default `target/titan-kernel/riscv64gc-unknown-none-elf/release/kernel`, with a clear error naming the build command if missing); interactive: stdin lines go to the shell, output to stdout; `--script` feeds a file then exits; `--disk` loads and saves a hades image (created with `/etc/shell` if missing).

## Tests
`tests/cli_titan.rs` as `docs/APPS.md` says: `--help`, `--version`, every subcommand on a good input, one bad input
each (exit 1 and a `titan:` message), an unknown subcommand (exit 2). Run `cargo fmt -p neon` before the gate.

## Report
`reports/T86n.md` (at most 10 lines): subcommands, anything left out and why, tests, gate last line.

## Extra check the leader will run
Release build, the tool by hand on fresh inputs, `bash tools/check.sh neon`.

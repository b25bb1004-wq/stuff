## Design (fixed by the leader)
- `Cargo.toml`: `crate-type = ["cdylib", "rlib"]`; depending on `neon` brings its exports (Titan, `logos_run`).
- `src/demos/mod.rs` (all targets): the registry.
  - `pub enum Output { Text(String), Pixels { w: u32, h: u32, rgba: Vec<u8> } }`
  - `pub struct Demo { pub id: &'static str, pub title: &'static str, pub default_input: &'static str,
    pub run: fn(&str) -> Result<Output, String> }` and `pub fn all() -> &'static [Demo]`, `pub fn find(id) -> Option<&Demo>`.
  - Every demo is pure (no threads, sockets, files, clocks), deterministic, bounded (step and size limits; a 64 KiB
    input cap), and finishes in under 50 ms natively on its default input.
  - One file per demo under `src/demos/`. This task's eight:
    `iridium` (run a SQL script on an in-memory `Db`: one result block per statement),
    `hades` (mkfs on a 256-block `MemDisk`, then a script of `mkdir`, `write PATH TEXT`, `cat`, `ls`, `rm` lines,
    then the `fsck` report), `chisel` (assemble RV64 source at `0x8000_0000`: hex dump with addresses),
    `silicon` (assemble then run up to 1 M steps on a 1 MiB machine: UART output, exit, final `a0`..`a7`),
    `lithium` (boot the lithium image for 2 M steps: UART transcript), `sphinx` (for the input text: SHA-256,
    SHA-512, HMAC-SHA256 with key `monolith`, ChaCha20 encrypt then decrypt round trip, Ed25519 sign and verify
    with a fixed demo seed; one line each), `logos` and `titan` are not in the registry: the page uses neon's exports
    for them directly (Logos playground, Titan terminal).
- `src/wasm.rs` (`cfg(target_arch = "wasm32")`): `site_demo(id_ptr, id_len, in_ptr, in_len) -> i32`: 0 = text ready,
  1 = pixels ready, 2 = error text ready; `site_last_ptr`, `site_last_len` for the bytes; `site_pixels_w/h` for the
  size. `site_list() -> len`: one line per demo, `id\ttitle`.
- `web/index.html`, `web/site.js`, `web/style.css`, `web/systems.js` (the 25 systems as data: number, name, what it
  is, one line, source folder, `demo` = registry id | `"titan"` | `"logos"` | `"athena"` | `null`):
  - Hero per `docs/FRONT.md`, then 25 sections in `docs/SPEC.md` order. A section with a demo shows an input
    (textarea prefilled with the default input), a Run button and an output (`<pre>` or `<canvas>`); a section with
    `demo: null` shows the line "Live demo coming in the next build" (T75b/c replace these).
  - Titan section: the neon terminal (boot on first visibility). Logos: the playground. Athena: a link to `athena/`
    (the packed Athena IDE) with a short description.
  - Motion and the pinned layer diagram exactly as `docs/FRONT.md` says; IntersectionObserver also lazy-loads:
    `site.wasm` loads when the first demo section nears the viewport, `titan.elf` only for the Titan section.
  - Every font, colour, size and duration from the tokens. 360 px, keyboard, focus ring, reduced motion, both themes.
- `src/pack.rs` (`cfg(not(target_arch = "wasm32"))`): `pub fn pack(out: &Path) -> Result<(), String>`: builds
  `site` for wasm32 release and the titan kernel (as neon does), writes `out/{index.html, site.js, style.css,
  systems.js, site.wasm, titan.elf}` and calls `athena::pack(&out.join("athena"))`. `examples/pack.rs` packs into
  `target/site-web`.

## Tests
- `tests/demos.rs`: every registered demo runs its default input to `Ok` in under 200 ms (debug build allowance) with
  output containing a fixed expected fragment per demo (e.g. the SHA-256 of `"abc"` when the input is `abc`, an
  `fsck` line with 0 errors, the lithium banner, a register value the silicon default program sets); bad input gives
  `Err` with a message, not a panic; `forall` over random byte inputs for each demo: no panic, bounded time.
- `tests/wasm_build.rs`: pack into `CARGO_TARGET_TMPDIR`; parse `site.wasm` exports (copy neon's reader): the site
  exports plus `titan_boot` and `logos_run`; imports empty or `env`; the six files plus `athena/index.html` exist;
  `index.html` and `site.js` reference only local paths; `systems.js` has 25 entries in SPEC order with unique numbers.

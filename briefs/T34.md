## Public API (crate root, exact)
```rust
pub const MAX_DATAGRAM: usize = 1200;
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Error { Timeout, Closed { code: u64, reason: String }, Protocol(&'static str), FlowControl,
    StreamLimit, TooLarge }
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Config { pub max_streams: u64, pub stream_window: u64, pub conn_window: u64,
    pub idle_timeout_ms: u64, pub max_half_open: usize }   // Default: 100, 262144, 1048576, 30000, 256
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub struct Stats { pub sent_packets: u64, pub lost_packets: u64, pub cwnd: u64,
    pub bytes_in_flight: u64, pub srtt_us: u64 }
#[derive(Debug, Clone)]
pub struct Connection;
impl Connection {
    pub fn connect(server_key: [u8; 32], seed: [u8; 32], config: Config, now: u64) -> Connection;
    pub fn cid(&self) -> u64;
    pub fn handle(&mut self, datagram: &[u8], now: u64);
    pub fn poll_transmit(&mut self, now: u64) -> Option<Vec<u8>>;
    pub fn timeout(&self) -> Option<u64>;          // absolute time of the next timer
    pub fn on_timeout(&mut self, now: u64);        // the caller calls it once now >= timeout()
    pub fn is_connected(&self) -> bool;            // handshake done (client: Response opened;
                                                   // server: first Data opened), false once closed
    pub fn is_closed(&self) -> bool;               // closed and done draining: nothing more to send
    pub fn error(&self) -> Option<Error>;          // why it closed (None while open)
    pub fn handshake_hash(&self) -> Option<[u8; 32]>; // h1 once known
    pub fn open_stream(&mut self) -> Result<u64, Error>;
    pub fn accept_stream(&mut self) -> Option<u64>; // streams the peer opened, each once, in order
    pub fn write(&mut self, id: u64, data: &[u8]) -> Result<usize, Error>; // bytes taken
    pub fn finish(&mut self, id: u64) -> Result<(), Error>;
    pub fn read(&mut self, id: u64, buf: &mut [u8]) -> Result<usize, Error>; // 0 = nothing now
    pub fn stream_finished(&self, id: u64) -> bool; // fin received and every byte read
    pub fn reset(&mut self, id: u64, code: u64) -> Result<(), Error>;
    pub fn close(&mut self, code: u64, reason: &str);
    pub fn stats(&self) -> Stats;
}
pub struct Server;
impl Server {
    pub fn new(secret: [u8; 32], seed: [u8; 32], config: Config) -> Server;
    pub fn public_key(&self) -> [u8; 32];
    pub fn handle(&mut self, datagram: &[u8], now: u64) -> Option<u64>; // cid it went to; None = dropped
    pub fn connection(&mut self, cid: u64) -> Option<&mut Connection>;
    pub fn accept(&mut self) -> Option<u64>;  // each connection once, when it becomes connected
    pub fn cids(&self) -> Vec<u64>;           // live connections, ascending
    pub fn timeout(&self) -> Option<u64>;
    pub fn on_timeout(&mut self, now: u64);   // runs due timers, removes closed and expired half-open
}
```

## Exact choices the doc leaves open
- Randomness: the client makes `rng = onyx::rng::ChaChaRng::from_seed(seed)`, fills `e_c` (32
  bytes) with `rng.fill`, then `cid = rng.next_u64()`. The server makes one `ChaChaRng` from its
  seed in `new` and fills 32 bytes of `e_s` for each new `cid` it accepts. Nothing else draws.
- Params are always all four ids in order 1, 2, 3, 4 with this side's `Config` values. The Initial
  plaintext is params then zeros up to 1134 bytes (so the datagram is exactly 1200); the
  receiver parses params and ignores the rest.
- Packet numbers per direction: the client's Initial is pn 0 (every resend is the identical
  datagram), its first Data packet pn 1; the Response is server pn 0, its first Data packet pn 1.
- On connecting the client at once sends a Data packet with an ACK frame for server pn 0 (the
  Response counts as an ack-eliciting packet); that packet connects the server side.
- `handle` of a packet that is dropped (doc section 3) changes nothing: the connection's Debug
  output is identical before and after. Server `handle` drops (None) Initials under 1200 bytes,
  that fail to open, with a low-order `E_c`, or beyond `max_half_open`; a repeat Initial for a
  known `cid` makes that connection queue the same Response again.
- `write` takes at most what keeps this stream's unacknowledged bytes within 1 MiB (it may take
  0). `read` after a peer reset is `Err(Error::Closed { code, reason: String::new() })`. Writing
  to a stream not open in that direction is `Protocol("unknown stream")`. `open_stream` beyond the
  peer's `max_streams` is `StreamLimit`. Any API call on a closed connection is its `error()`.
- Idle timeout: closed with no packet sent, `error() == Some(Timeout)`. Client giving up after 6
  Initials: `Timeout`. Receiving CLOSE: `error() == Some(Closed { code, reason })`; the side that
  calls `close(code, reason)` also reports that.
- Every datagram sent is at most 1200 bytes; a server never sends more bytes to an unconnected
  client than it received from it.

## Tests required
`tests/tremor.rs`: handshake round trip and the resend rules, a channel simulator with loss,
reordering, duplication and corruption (each up to 30 percent) moving several streams both ways
byte-exact, flow control limits, stream limits, reset, close and idle timeout, congestion window
rules (`bytes_in_flight <= cwnd + 1200`, `cwnd >= 2400`), replayed and corrupted packets
changing nothing, fuzzed datagrams never panicking.

stream limit, close codes, idle timeout and random datagram fuzzing.

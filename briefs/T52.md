## Design (fixed by the leader)
- **Image** = an installed argo package. `pandora::image`:
  - `pull(registry: SocketAddr, name: &str, req: &Req, store: &Path, trusted: &[[u8; 32]]) -> io::Result<Solution>`:
    `argo::install` into `store` (argo's own layout under `store/pkgs`, `store/argo.lock`).
  - `build_rootfs(store: &Path, image: &str, dest: &Path) -> io::Result<()>`: from `argo::installed(store)`, take the
    image and its transitive dependencies, copy their files into `dest` dependencies first (a dependency before anything
    that depends on it, ties by name), the image last; later files overwrite earlier ones. Reject (error, nothing
    written outside `dest`) any file path that is absolute, contains `..`, or would land outside `dest`. Copy the
    executable bit: files under `bin/` or `usr/bin/` or ending in `.sh` get mode 0755 on Unix.
- **Store state** `pandora::state`: each container is `store/containers/<id>/` with `rootfs/` and a `state` file of
  `key=value` lines: `image`, `status` (`created`, `running`, `exited`), `pid` (host pid of the container's PID 1),
  `exit` (code). `id` is given with `--name` (validated like a hostname, at most 32 chars) or generated as
  `c<unix-nanos-hex>`. An existing id is an error. Writes are atomic (write `state.tmp`, rename). `list(store)` returns
  all containers sorted by id; a `running` container whose pid is gone (no `/proc/<pid>` on Linux) reads as
  `exited` with exit `-1`.
- **Linux (`sys.rs`)**: child A reports child B's pid to the parent through the existing `up` pipe (4 bytes,
  little-endian) right after the second fork. `run` gets an optional callback or out-parameter receiving that pid so the
  caller can write `pid=` before waiting. Add `pub fn kill(pid: i32, sig: i32) -> io::Result<()>` via libc `kill`.
- **CLI** (`src/bin/pandora.rs`), all with `--store DIR` (default `$HOME/.pandora`):
  - `pandora pull --registry HOST:PORT --trust HEX64 NAME[@REQ]` (REQ default `*`).
  - `pandora run --image NAME [--name ID] [-d] [existing T51 flags] [-- CMD...]`: builds the rootfs, runs, records
    state; prints nothing extra in the foreground and exits with the container's code. `-d` re-executes itself
    (`std::env::current_exe`) as a hidden `pandora __supervise --store DIR ID ...`, prints the id and returns 0; the
    supervisor writes `running` + pid, waits, writes `exited` + code. `--rootfs` stays valid without `--image` (T51).
  - `pandora ps`: header `ID IMAGE STATUS` then one line per container, `STATUS` is `running`, `exited(<code>)` or
    `created`, columns separated by two spaces.
  - `pandora kill ID [SIGNAL]` (default 9, numeric only): signals the recorded pid; error if not running.
  - `pandora rm ID`: removes the container directory, refusing a running one.
- Exit codes stay as T51 (125 pandora error).

## Tests
- `tests/image.rs` (all platforms): a local `argo::Registry` on `127.0.0.1:0`, a test publisher key, publish `base 1.0.0`
  (`bin/tool` = some bytes) and `app 1.0.0` depending on `base ^1` (`app/run.sh`, plus a `bin/tool` override);
  `pull app` installs both; `build_rootfs` gives the override, both files, correct order; a package with `../x` or `/x`
  is rejected and nothing escapes; `state` round trip, `list` order, duplicate id error, atomic write leaves no
  `state.tmp`.
- `tests/linux_images.rs` (`cfg(target_os = "linux")`, skip like `linux_run.rs` when user namespaces are blocked): a
  `base` package holding host `/bin/sh`, `/bin/sleep` and their `ldd` libraries, `app` with `app/hello.sh`
  (`echo hello from app`); `pull`, `run --image app -- /bin/sh /app/hello.sh` prints it and exits 0; `run -d` with
  `/bin/sleep 30`, `ps` shows `running`, `kill`, then `ps` shows `exited(137)` within 5 s; `rm` works after.

# T86k tool (crates/indium): the `indium` command-line tool
Worker: hydrogen-high (agy). Budget: one run, at most 90 minutes. First read `briefs/_RULES.md`, then `docs/APPS.md`
(the "Tool conventions" section and the `indium` row; those rules are part of this brief), then only the public

**May touch:** `crates/indium/src/bin/indium.rs`, `crates/indium/tests/cli_indium.rs`, `crates/indium/Cargo.toml`
(a `[[bin]]` entry or a path dependency already in the workspace, never one that creates a cycle) only. Do not
change library code; if a subcommand needs something the library does not offer, leave it out and say so. Zero
external crates. Your gate is `bash tools/check.sh indium`; you can only run commands for `indium`.

## Tool
- `indium`: `render LAYOUT --out UI.png [--width W --height H]`: LAYOUT is a small indented text format (one widget per line: `column`, `row`, `text "..."`, `button "..."`, `list N`), documented in `--help`; prints the focus order; `--focus N` draws the focus ring on the N-th widget.

## Tests
`tests/cli_indium.rs` as `docs/APPS.md` says: `--help`, `--version`, every subcommand on a good input, one bad input
each (exit 1 and a `indium:` message), an unknown subcommand (exit 2). Run `cargo fmt -p indium` before the gate.

## Report
`reports/T86k.md` (at most 10 lines): subcommands, anything left out and why, tests, gate last line.

Release build, the tool by hand on fresh inputs, `bash tools/check.sh indium`.

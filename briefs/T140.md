## Build
- `Door` device exactly as contract C1: window `0x1000_4000`, size `0x1000`, PLIC source 12, registers
  and semantics as the table says, inbox cap 64 frames, max frame 1 MiB, dropped counter.
- Wire it into the board's `read` and `write` dispatch and into `device_lines` (IRQ) like keys.
- Public on `Machine`: `door_push_to_guest(&mut self, channel: u8, bytes: &[u8])`,
  `door_take_from_guest(&mut self) -> Vec<(u8, Vec<u8>)>`, `door_dropped(&self) -> u64`.
- Snapshot: door registers and both queues save and restore. Keep old snapshot loading working if the
  format has a version; if adding the door changes the format, bump the version and say so in the report.

## Accept (tests)
1. Guest-to-host: write a frame into RAM, set TX_ADDR/TX_LEN/TX_CHAN through bus writes (or a tiny RV64
   program), write TX_GO, `door_take_from_guest` returns exactly that (channel, bytes); TX_ERR clear.
2. TX range outside RAM or TX_LEN 0 or > 1 MiB: TX_ERR set, nothing queued.
3. Host-to-guest: push two frames; STATUS bit 0 set, RX_LEN and RX_CHAN show the first; RX_TAKE copies it
   into RAM at RX_ADDR and pops; then the second shows.
4. Front frame longer than RX_CAP: RX_TAKE sets bit 2 and the frame stays queued.
5. 65th push is dropped and `door_dropped()` is 1.
6. IRQ: with IRQ_ENABLE set and a frame queued, the PLIC line for source 12 is raised.
7. Snapshot taken with frames queued restores them.
8. Property test (assay `forall`): random frames pushed then taken by the guest arrive unchanged in order.

Gate: `bash tools/check.sh silicon` ends with `CHECK PASS silicon`.

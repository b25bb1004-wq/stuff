# T86l tool (crates/athena): the `athena` command-line tool
Worker: hydrogen-high (agy). Budget: one run, at most 90 minutes. First read `briefs/_RULES.md`, then `docs/APPS.md`
(the "Tool conventions" section and the `athena` row; those rules are part of this brief), then only the public
items of `crates/athena/src/lib.rs` and the modules they point to that you call. Read nothing else.
**May touch:** `crates/athena/src/bin/athena.rs`, `crates/athena/tests/cli_athena.rs`, `crates/athena/Cargo.toml`
(a `[[bin]]` entry or a path dependency already in the workspace, never one that creates a cycle) only. Do not
change library code; if a subcommand needs something the library does not offer, leave it out and say so. Zero
external crates. Your gate is `bash tools/check.sh athena`; you can only run commands for `athena`.

## Tool
- `athena`: `check FILE.logos` (diagnostics as `file:line:col: error: message`, exit 1 if any), `fmt FILE.logos [--write]` (prints formatted source or rewrites it; refuses files with comments, exit 1), `test FILE.logos` (runs tests and props, prints pass/fail lines, exit 1 on any failure). Host only.

## Tests
`tests/cli_athena.rs` as `docs/APPS.md` says: `--help`, `--version`, every subcommand on a good input, one bad input
each (exit 1 and a `athena:` message), an unknown subcommand (exit 2). Run `cargo fmt -p athena` before the gate.

## Report
`reports/T86l.md` (at most 10 lines): subcommands, anything left out and why, tests, gate last line.

## Extra check the leader will run
Release build, the tool by hand on fresh inputs, `bash tools/check.sh athena`.

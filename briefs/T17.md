## Public API (exact; Sinter, Seam and the Lapidary debugger are written against it)
```rust
pub struct Heap;
impl Heap {
    pub fn alloc(&mut self, obj: Obj) -> Result<Handle, Trap>;   // OutOfMemory if over the limit (no collection here)
    pub fn get(&self, h: Handle) -> Result<&Obj, Trap>;           // TypeError for a free or unknown handle
    pub fn get_mut(&mut self, h: Handle) -> Result<&mut Obj, Trap>;
    pub fn live_objects(&self) -> usize;
    pub fn live_bytes(&self) -> usize;
}
pub trait Host { fn call(&mut self, name: &str, args: &[Value], heap: &mut Heap) -> Result<Value, Trap>; }
pub struct NoHost;                                // impl Host: every call is Err(Trap::Host("no host".into()))
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Limits { pub fuel: u64, pub max_heap_bytes: usize, pub max_depth: u32 }  // Default: 10_000_000, 64 MiB, 1024
#[derive(Debug, Clone, PartialEq)]
pub enum LoadError { Verify(VerifyError), MissingImport(String) }
pub struct Vm;
impl Vm {
    pub fn new(module: Module, host_names: &[&str]) -> Result<Vm, LoadError>;  // verify, then every import must be in host_names
    pub fn run(&mut self, host: &mut dyn Host, limits: Limits) -> Result<Value, Trap>;   // entry with no args; entry.params != 0 is TypeError
    pub fn call(&mut self, func: &str, args: &[Value], host: &mut dyn Host, limits: Limits) -> Result<Value, Trap>; // unknown name or wrong arg count: TypeError
    pub fn heap(&self) -> &Heap;
    pub fn heap_mut(&mut self) -> &mut Heap;
    pub fn fuel_used(&self) -> u64;               // of the last run or call
}
```
The heap persists across `run` and `call` on the same `Vm` (a host may keep handles it returned),
but a collection only keeps what is reachable from live frames at that moment.

## Behaviour (fixes what `docs/MBC.md` leaves open; it must be identical on every machine)
- **Frames.** A call makes a frame of `regs` registers, all `Unit`, arguments copied to `0..n`.
  `Ret(a)` writes the value to the caller's `d`. Depth above `max_depth` frames: `StackOverflow`.
  The interpreter loop is iterative with its own frame stack; no Rust recursion anywhere.
- **Object size** (for `live_bytes` and the heap limit): 16 + payload, where payload is the byte
  length for `Str` and `Bytes`, and 16 per `Value` for `Array`, `Record`, `Variant`.
- **Fuel.** Every instruction costs 1. Extra cost: an instruction that creates an object pays 1 per
  element (Array, Record, Variant) or `ceil(len / 8)` for Str and Bytes, of the object it creates
  (`Const`, `New*`, `Slice`, `Concat`, `IntToStr`, `ParseInt` result, `StrToBytes`,
  `BytesToStr`, `Pop` result). `Eq Ne Lt Le Gt Ge` on Str or Bytes pay `ceil(min(len_a, len_b) / 8)`.
  `Push` pays 1. `NewFill` pays its count (or `ceil(count / 8)` for Bytes) BEFORE allocating.
  Before an instruction runs, if `used + cost > limits.fuel` the run stops with `OutOfFuel` and
  the instruction has no effect. `fuel_used` then equals the fuel spent by the completed instructions.
- **Heap limit.** Check the size of a new object BEFORE building it (a `NewFill` of 2^40
  elements must give `OutOfMemory` or `OutOfFuel`, never a Rust allocation failure). When
  `live_bytes + size > max_heap_bytes`, collect, then retry once, then `OutOfMemory`.
- **Collector.** Mark and sweep over a slot table with a LIFO free list; roots are every register
  of every live frame plus the value being returned. Also collect when bytes allocated since the
  last collection exceed `max(1 MiB, live bytes after the last collection)`. Marking uses an
  explicit work list (deep object graphs must not overflow the Rust stack). Objects never move.
- **Operands.** Wrong kinds are `TypeError` (for example `Add` of Int and Byte, `And` on Byte,
  `JumpIf` on Int, `Push` of an Int into Bytes, `Eq` on two Arrays, `GetField` on an Array).
  Negative or too large index, field number or `NewFill` count: `IndexOutOfRange`.
  `Slice` needs `0 <= lo <= hi <= len` and char boundaries for Str, else `IndexOutOfRange`.
- **Conversions.** `IntToStr` is plain decimal with a leading `-` for negatives. `ParseInt`
  accepts exactly `-?[0-9]+` that fits i64 and gives `some(Int)`, else `none`.
  `none` is `Variant { tag: 0, fields: [] }`, `some(v)` is `Variant { tag: 1, fields: [v] }`.
- `CallHost` passes the argument registers as a slice and the heap; the host's `Err` stops the run.
- No call panics, whatever module passes the verifier and whatever the limits are.

## Tests required
- One directed test per opcode (hand-built `Module`s), including each trap it can raise.
- Programs: iterative and recursive factorial, Fibonacci, building a string in a loop, a linked
  list of records, an array of variants walked with `Tag`/`GetField`.
- Fuel: a loop of N iterations costs an exact count you derive in the test; fuel `k` for every
  `k` below the full cost stops with `OutOfFuel` and `fuel_used <= k`.
- GC: a loop that allocates 100 000 garbage objects under a 1 MiB heap finishes, and
  `live_objects` stays small; a loop that keeps every object gives `OutOfMemory`.
- Recursion depth 1 000 000 with `max_depth` 1 000 000 runs or stops cleanly (no Rust stack overflow);
  above the limit gives `StackOverflow`.
- Fuzz (`forall`, at least 1000 cases): `testgen::random_module`, run with small fuel and heap
  under `NoHost` and a counting host: never panics; running twice gives the same result and the
  same `fuel_used`.

## Demos (each `src/demos/<id>.rs`, short `default_input`, pure, deterministic, bounded, never panics; input over
`MAX_INPUT_BYTES` is an error; `Pixels` at most 640x400)
- `odyssey`: input is HTML (+ inline `<style>`); output `Pixels` of the page painted at 480 px wide (the crate's
  layout and paint), errors as text.
- `indium`: input is the layout text format the `indium` tool uses (`crates/indium/src/bin/indium.rs` `--help` text
  only: `column`, `row`, `text`, `button`, `list N`, a final `focus N` line); output `Pixels` with the focus ring.
- `iris`: input is the event script the `iris` tool uses (its `--help` text only); output `Pixels` of the final
  desktop frame. If `iris` needs anything that does not build for wasm, skip it.
- `helios`: input is a small Logos game (default: a short version of `crates/helios/src/game.logos`) plus a
  `ticks N` first line; output `Pixels` of the last frame, or text with the world hash if the crate has no frame
  buffer you can reach.
- `xenon`: input lines `loss P`, `delay N`, `send TEXT` over the crate's in-memory lossy link (no sockets); output
  text: delivered in order, retransmits, the stats.
- `pandora`: input is a container spec in the crate's format; output text: the parsed and validated spec, limits,
  and the error for a bad spec. Parsing only; nothing runs.
- `midas`: only if the crate offers a safe constructor (for example over an owned buffer); input the trace format of
  the `midas` tool (`allocs`, `free N`); output text per step. Otherwise skip it and say so.
- Zeus is out of scope here.

## Scope (exact)
- `SELECT ... FROM t [AS a] [[INNER | LEFT] JOIN u [AS b] ON e]...` with any number of joins:
  nested loops in the written order; LEFT JOIN emits the left row with NULLs when no right row
  matches. `t.c` and `a.c` references; an unqualified name found in two tables is
  `Parse { pos, msg }` with msg containing "ambiguous" (SQLite: "ambiguous column name"). `*`
  expands to every column of every table in order; the result names are the bare column names.
  WHERE, GROUP BY, HAVING, ORDER BY, DISTINCT, LIMIT all work on joined rows as on single tables.
- Index use: the planner of section 6. A table is searched by rowid for `rowid = e` or
  `ipk = e`, else by the index (created order, first match wins) whose leading columns all have an
  equality term, optionally followed by one range term (`<`, `<=`, `>`, `>=`, BETWEEN), where the
  terms are top-level AND-ed WHERE terms (or the ON term for the inner table of a join) comparing
  the column with an expression not using that table. Results must equal the scan's results
  (including NULL, type and collation behaviour); only speed differs.
- `EXPLAIN SELECT ...` returns one column named `plan` and one row per table in join order:
  `SCAN t`, `SEARCH t USING ROWID`, or `SEARCH t USING INDEX i (a=? AND b>?)` listing the terms
  used in index column order (`=` terms as `c=?`, the range as `c>?`, `c<?`, `c>=?`, `c<=?`, a
  BETWEEN as `c>? AND c<?`). Aliases do not change the printed table name.
- `changes`, errors and transactions behave as in T41a.

## Public API (exact, in `varve::sql`)
```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Value { Null, Int(i64), Text(String), Blob(Vec<u8>) }
#[derive(Debug, Clone, PartialEq, Eq, Default)]
pub struct Rows { pub columns: Vec<String>, pub rows: Vec<Vec<Value>>, pub changes: u64 }
pub struct Db<S: Storage>;
impl<S: Storage> Db<S> {
    pub fn open(main: S, log: S) -> Result<Db<S>, Error>;  // creates the catalog on an empty file
    pub fn execute(&mut self, sql: &str) -> Result<Rows, Error>; // exactly one statement, optional `;`
    pub fn in_transaction(&self) -> bool;
    pub fn close(self) -> Result<(S, S), Error>;
}
pub fn encode_key(values: &[Value]) -> Vec<u8>;     // VARVE.md section 5 key encoding
pub fn encode_record(values: &[Value]) -> Vec<u8>;  // section 5 row record
pub fn decode_record(bytes: &[u8]) -> Result<Vec<Value>, Error>;
```

## Scope of T41a (T41b adds joins, index use in plans and EXPLAIN)
- **Parser for the whole section 6 grammar**, including JOIN and EXPLAIN syntax. In this task a
  SELECT with a JOIN, or EXPLAIN, returns `Error::Misuse`; everything else in section 6 executes.
  Parse errors are `Parse { pos, msg }` with the byte offset of the offending token.
- Catalog in the page 0 tree exactly as section 5; `CREATE TABLE`, `DROP TABLE`, `CREATE [UNIQUE]
  INDEX`, `DROP INDEX`. Name clashes are `Exists`; unknown names `NoSuchTable`/`NoSuchColumn`.
- Tables keyed by rowid, `INTEGER PRIMARY KEY` as rowid, new rowid = max + 1. Every index (and
  every implicit unique index for `UNIQUE` or a non-integer `PRIMARY KEY`) is maintained on
  INSERT, UPDATE and DELETE and enforces uniqueness (`Constraint("UNIQUE ...")`; NULLs never
  clash, as SQLite). NOT NULL gives `Constraint("NOT NULL ...")`. Wrong types give `Type`.
- `INSERT` (with or without a column list; missing columns are NULL), `UPDATE`, `DELETE`, and
  single-table `SELECT` with `DISTINCT`, `*`, aliases, `WHERE`, `GROUP BY`, `HAVING`, aggregates,
  `ORDER BY` (several keys, ASC/DESC, NULLs first in ASC), `LIMIT`/`OFFSET`; a SELECT without FROM
  (`SELECT 1 + 2`) works. Plans are scans (index use comes in T41b; results must not change).
- Expressions, functions, three-valued logic, cross-type comparison and overflow exactly as
  section 6; `/` and `%` by zero give NULL.
- Result column names: the `AS` alias; else the bare column name for a column reference; else the
  expression text exactly as written in the statement (SQLite's rule). `changes` counts rows
  inserted, updated or deleted by the statement (0 for SELECT and DDL).
- Transactions: autocommit per statement; `BEGIN`/`COMMIT`/`ROLLBACK` as section 4 (`Misuse` for
  COMMIT or ROLLBACK outside a transaction, or BEGIN inside one). A failing statement changes
  nothing, also inside an explicit transaction (plan the whole statement's changes, check them,
  then apply). Everything persists across `close` and `open` of the same storages.

hostile bytes never panic), every statement form, each constraint, NULL logic tables, every

property test that random SQL text never panics `execute`.

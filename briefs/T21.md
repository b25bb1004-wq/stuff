## Why
The kernel (T25), cobalt's back end and the boot tests need an assembler inside Monolith. Every
byte it emits must equal what LLVM emits for the same source (the reference is rustc's LLVM 19).

## Public API (crate root, exact)
```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Output { pub bytes: Vec<u8>, pub symbols: Vec<(String, u64)> }
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct AsmError { pub line: usize, pub msg: String }      // line is 1-based
impl std::fmt::Display for AsmError { /* "line {line}: {msg}" */ }
pub fn assemble(src: &str, base: u64) -> Result<Output, AsmError>;
```
One flat section: every byte goes into `bytes`, the first at address `base`. `symbols`: every named
label (not numeric labels, not `.equ` constants) with its absolute address, in definition order.

## Source syntax
- One statement per line. `#` starts a comment (not inside a string). Any number of labels
  `name:` may precede a statement on the same line, or stand alone. Names: `[A-Za-z_.$][A-Za-z0-9_.$]*`.
- Numeric labels `N:` (decimal). `Nb` = the latest `N:` defined at or before this line (so
  `1: j 1b` jumps to itself); `Nf` = the next `N:` after this line. They may be redefined freely.
- Registers `x0`..`x31` and ABI names (`zero ra sp gp tp t0-t6 s0-s11 fp a0-a7`). Lowercase.
- Integers: decimal, `0x` hex, `0b` binary, `'c'` character. Expressions over integers, constants
  and labels with LLVM's (GNU) precedence, all left-associative, 64-bit wrapping:
  unary `- ~ +` > `* / % << >>` > `| & ^` > `+ -`; parentheses. `>>` is logical; `/` and `%`
  truncate toward zero. Examples from LLVM: `6 & 3 - 1` = 1, `1 + 2 << 3` = 17, `5 | 2 ^ 3` = 4,
  `-7 / 2` = -3, `-8 >> 60` = 15.
- A label's value is its absolute address. `label - label` is a plain number.
- `%hi(e)`, `%lo(e)` of absolute expressions (constants or labels): `%hi` = `((e + 0x800) >> 12)
  & 0xfffff`, `%lo` = low 12 bits sign-extended. `%pcrel_hi(L)` on an `auipc` at address P gives the
  hi part of `L - P`; `%pcrel_lo(X)` takes the label X of that auipc and gives the matching lo part
  of `L - P` (not `X`'s own address). `%pcrel_lo` of a label that is not on such an auipc is an error.
- `.equ NAME, expr` and `.set NAME, expr`: constants; the expression may only use constants and
  labels defined earlier in the file. Redefinition is allowed; later uses see the newest value.

## Instructions
- Every instruction silicon's `Inst` names (RV64I, M, A, Zicsr, `fence.i`, `ecall`, `ebreak`, `mret`,
  `sret`, `wfi`, `sfence.vma rs1, rs2`), with LLVM's operand syntax: loads/stores `imm(rs1)`, where
  `(rs1)` means offset 0; LR/SC/AMO `(rs1)` or `0(rs1)` with suffixes `.aq .rl .aqrl`; CSRs by number
  (0..4095) or by the names below; `csrr*i` immediates 0..31.
- `fence pred, succ` with sets from `iorw` (any non-empty subset in that order); bare `fence` =
  `fence iorw, iorw`. Encode fence yourself (silicon's `Inst::Fence` has no fields): fm=0,
  pred<<24 | succ<<20 | 0x0f.
- CSR names: cycle 0xC00, time 0xC01, instret 0xC02, sstatus 0x100, sie 0x104, stvec 0x105,
  scounteren 0x106, sscratch 0x140, sepc 0x141, scause 0x142, stval 0x143, sip 0x144, satp 0x180,
  mvendorid 0xF11, marchid 0xF12, mimpid 0xF13, mhartid 0xF14, mstatus 0x300, misa 0x301,
  medeleg 0x302, mideleg 0x303, mie 0x304, mtvec 0x305, mcounteren 0x306, mscratch 0x340, mepc 0x341,
  mcause 0x342, mtval 0x343, mip 0x344, mcycle 0xB00, minstret 0xB02.
- Pseudo-instructions (LLVM expansions): `nop mv not neg negw sext.w seqz snez sltz sgtz`,
  `beqz bnez blez bgez bltz bgtz bgt ble bgtu bleu`, `j L`, `jal L` (rd = ra), `jal rd, L`, `jr rs`,
  `jalr rs` (rd = ra), `jalr rd, imm(rs)`, `ret`, `call L` (auipc ra + jalr ra, ra), `tail L`
  (auipc t1 + jalr zero, t1), `lla rd, L` and `la rd, L` (both auipc rd + addi rd, rd),
  `csrr csrw csrs csrc csrwi csrsi csrci`, `rdcycle rdtime rdinstret`, `li rd, expr`.
- `li rd, expr`: expr must be absolute (no labels). Size rule (the corpus depends on it): a value in
  -2048..=2047 is one `addi rd, zero, v`; an i32 value with low 12 bits zero is one `lui`; any other
  i32 value is exactly 2 instructions; values outside i32 use any sequence of at most 8
  instructions that leaves exactly that 64-bit value in rd and changes no other register
  (checked by running it).
- Explicit compressed instructions `c.*` (all of RV64C: `c.addi4spn c.lw c.ld c.sw c.sd c.nop
  c.addi c.addiw c.li c.addi16sp c.lui c.srli c.srai c.andi c.sub c.xor c.or c.and c.subw c.addw c.j
  c.beqz c.bnez c.slli c.lwsp c.ldsp c.jr c.mv c.ebreak c.jalr c.add c.swsp c.sdsp`) with LLVM's
  operand syntax and constraints; `c_pairs.txt` has 2500 LLVM-checked examples (halfword, then
  the c.* line before `|`). Never compress a plain instruction.
- Branch/jump targets must be in range (B: ±4 KiB, J: ±1 MiB, c.beqz/c.bnez ±256 B, c.j ±2 KiB)
  and even; out of range is an error (no relaxation). Immediates out of range are errors. A target
  that is a plain number (no symbols), as in `beq a0, a1, -8` or `c.j 100`, is the PC-relative
  offset itself, as in LLVM.

## Directives
- Ignored (accept any arguments): `.option`, `.text`, `.data`, `.section`, `.globl`, `.global`,
  `.type`, `.size`, `.file`, `.attribute`.
- Data: `.byte` (-128..=255), `.half`/`.2byte` (-32768..=65535), `.word`/`.4byte`/`.long`
  (-2^31..=2^32-1), `.dword`/`.8byte`/`.quad` (any 64-bit), each a comma list of expressions,
  little-endian; `.zero n`/`.space n`; `.ascii`/`.asciz`/`.string` with escapes `\n \t \r \0 \\ \"`.
  No alignment is inserted before data.
- Alignment: `.balign n` (n a power of two), `.p2align k` and `.align k` (both 2^k). Padding, as
  LLVM emits it: zero bytes up to an even address, then `c.nop` (01 00) if at 2 mod 4, then `nop`
  words (13 00 00 00).
- `.macro NAME a, b` ... `.endm`; invoke as `NAME x, y` (commas); `\a` in the body is replaced by
  the argument text. Numeric labels inside work per expansion. A missing `.endm` is an error at the
  `.macro` line; errors inside an expansion report the invoking line.
- Anything else starting with `.` is an error (`unknown directive`).

## Errors
Return the first error by line. Required cases (the message wording is yours): unknown mnemonic,
unknown register, wrong operand count, immediate out of range, shift amount out of range,
undefined symbol, duplicate label, branch out of range, `c.*` operand constraint (e.g.
`c.lw ra, 0(a0)`, `c.addi a0, 0`), unknown directive, missing `.endm`, `Nf` with no later `N:`,
bad `%pcrel_lo` target, data value out of range, unterminated string.

## Tests required
Unit tests for every instruction format and pseudo, expressions, both label kinds, macros,
alignment from each offset mod 8, every error case above with its line number, and a property
test: random programs assemble identically twice and labels resolve to the bytes they name.

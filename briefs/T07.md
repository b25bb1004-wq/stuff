## Public API (added; exact)
```rust
pub struct Report { pub errors: Vec<String>, pub fixed: usize }   // Debug, Clone, PartialEq, Eq
pub fn fsck<D: BlockDevice>(dev: &mut D, repair: bool) -> Result<Report, Error>;  // read-only when repair is false
pub struct CrashDisk<D: BlockDevice>;          // wraps a device; drops every write after the first `budget` writes
impl<D: BlockDevice> CrashDisk<D> {
    pub fn new(inner: D, budget: u64) -> CrashDisk<D>;
    pub fn writes(&self) -> u64;               // writes attempted so far
    pub fn into_inner(self) -> D;
}
// impl BlockDevice for CrashDisk<D>: after the budget, `write` returns Ok but changes nothing,
// and `flush` returns Ok. (A torn single block is not modelled: block writes are atomic.)
```
Add an `Error` variant only if you must, and say why in the report.

## Behaviour
- Write-ahead journal in a fixed region that `mkfs` reserves (size your choice, recorded in the
  superblock; bump the format version). Commit: write the changed blocks to the journal, a commit
  record with a CRC-32C over them, flush, then write the blocks home, flush, then mark the journal
  empty. `mount` replays a complete committed transaction and ignores a torn one.
- A transaction larger than the journal is split so that each piece leaves a consistent file
  system, or refused with an error before anything is written. Say which in the report.
- `fsck` checks: superblock CRC, every inode CRC, extents inside the data area, no block owned
  twice (this closes the T06 gap: overlapping extents across files), the bitmap equals the set
  of owned blocks, directory entries point at live inodes, link counts, no orphan inodes, sizes
  agree with extents. With `repair`, fix bitmap and orphan problems; report the rest.
- No call panics on any disk content.

## Tests required
- Crash injection: for random operation sequences (create, write, truncate, rename, remove,
  mkdir), run once to count the writes W, then for every budget `b` in `0..=W` replay on a
  `CrashDisk` with budget `b`, remount the inner disk, and check: mount succeeds, `fsck` reports
  no errors, and the visible tree equals either the state before or after each operation
  (keep a shadow model of every operation boundary). At least 100 sequences of 30 operations.
- fsck finds each planted fault: double-owned block, bitmap bit cleared, entry to a free inode,
  wrong link count, orphan inode; `repair` fixes the fixable ones and a second run is clean.
- The T06 property tests still pass.

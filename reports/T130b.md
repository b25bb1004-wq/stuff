# T130b feed.js: Titan counters to board events

Status: done, not committed. Brief: briefs/T130-board.md (split T130b).

## Built
- crates/site/web/feed.js: `window.Feed.start(titanApi, emit) -> stop`. The mapping table is at the top of the file.
  Each tick reads titan_probe, parses the `name value` lines, diffs against the previous tick and emits per (kind, from, to) group.
  Timing: one `Motion.tween(Infinity)` job on the kit frame loop. Reduced motion falls back to a setTimeout chain (no setInterval).
- crates/site/tests/feed_lint.rs: `lint_page` on feed.js is clean; checks the `window.Feed` export and no `setInterval(`.
- scripts/feed-check.mjs: Node 18+, no packages. Loads the neon wasm through kit/wasm.js, boots target/athena-web/titan.elf, starts Feed, sends `ls`, pumps Titan and prints the events. Exits 1 on failure.

## Mapping (decided from the 69 real probe lines and the ids in systems.js)
- ecall.count: ecall, titan to silicon (brief's direction)
- exception.NN and interrupt.NN (summed): trap, silicon to titan
- uart.out: uart, titan to iris; uart.in: uart-in, iris to titan
- block.reads: block-read, titan to hades; block.writes: block-write, titan to hades

## Deviations and limits
- systems.js has no `deps` field, so the pairs come from the counter names, not from the dependency graph.
- Interrupts are folded into `trap`. Counters that go down (seek rewind) are treated as resets, not events.
- The first tick after start is a baseline and emits nothing.
- Cap: 8 emits per tick. Groups past the eighth are added to the eighth's count. The table has 6 groups, so the cap is not reached today.
- Feed does not pump Titan. The terminal pump does. While started, Feed keeps the kit frame loop awake, which the motion rule "sleeps when no pulse is live" does not allow. Upgrade: drive Feed from the pump once site.js exposes it.
- titan_probe is read through the raw exports; titan_probe returns the text in the last buffer.

# T75d: iris demo traps in wasm

- Cause: `iris` opens a terminal, which calls `krypton::exec::Shell::new()`, which reads `std::env::vars()`; that traps on wasm32-unknown-unknown (confirmed under node: stack ends in `std::env::vars_os`).
- Fix (crates/site/src/demos/iris.rs): the default script no longer opens a terminal (editor + files); `open terminal` on wasm32 returns a clean `Err` line instead of building a Shell. Native behaviour unchanged.
- Test (crates/site/tests/iris_demo.rs): default script and a files-only script render 640x400 via `demos::find("iris")`, and a terminal request returns Err, not a panic.
- Open: apps/iris/app.js examples 2 and 3 still start with `open terminal` (file outside this brief), so they now show the clean error in the browser; fixing them needs a separate brief.
- Gate: `CARGO_TARGET_DIR=/c/Users/ADMIN/strata-gate-target/h-site bash tools/check.sh site` ends with `CHECK PASS site`.

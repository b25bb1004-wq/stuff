# T80 security review: chronos (read-only; nothing executed)
Read: remote/server.rs (all), remote/pack.rs decode_pack, remote/http.rs client, store.rs validate_path, validate_branch_name and DirStore::disk_path, index.rs flatten_tree_to_index, format.rs decode_tree, repo.rs checkout and add, bin/chronos.rs checkout and materialize. lib.rs forbid(unsafe_code).
HIGH H1 checkout writes outside the repo on Windows: format.rs:93 rejects only '/' in tree entry names; index.rs:112 rejects only "." and ".."; bin/chronos.rs:322-328 pushes each component as-is and bin/chronos.rs:364-370 writes it. Windows treats '\' and drive prefixes as separators. Input: a tree entry named ..\..\..\Users\ADMIN\Startup\x.bat or C:x, reached by `checkout <commit-hex>` (repo.rs checkout accepts any resolvable id). Fix: run validate_path-style checks on every component in flatten_tree_to_index and reject '\' and ':'.
MEDIUM M1 remote/server.rs:23-55: serve() mounts GET /refs, POST /fetch and POST /push with no authentication. handle_push (167-233) writes objects (193) and refs (226-228) for any caller. Input: unauthenticated POST to the push route with a valid DPK1 pack and an update line whose old id matches the public /refs output moves a branch. Fix: require a shared token or bind to localhost, and document that serve() must not be exposed as-is.
LOW L1 remote/http.rs:81: plain HTTP only; refs are unauthenticated and pack integrity is a bare SHA-256 trailer (pack.rs:62-66, not a signature), so an on-path attacker can substitute history. Fix: TLS or signed refs.
LOW L2 server.rs:173-194: no per-repo quota or rate limit; each push can write up to 100k objects and 64 MiB. Fix: quota or request limit.
No finding (sampled): pack.rs:53-82 count and size caps; http.rs:96-120 64 MiB read cap and timeouts; store.rs:140-179 path and branch validation (rejects "..", leading '.', '/', non-ASCII); server.rs handle_push checks branch names before any ref write.

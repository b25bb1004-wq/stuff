- Built: write-ahead journal (commit record "SHJRNL02" with CRC-32C over logged copies and itself; magic bumped to SHALE002, journal must be at least 2 blocks); blocks free before the operation are written home directly, only in-use blocks go through the journal; mount replays a complete commit and drops a torn one.
- Built: `fsck(dev, repair)` returning `Report { errors, fixed }` (superblock, journal, inode CRCs and kinds, extents, double ownership, orphans, link counts, directory entries, bitmap); `CrashDisk` with `new`, `writes`, `into_inner`.
- Gate last line: `CHECK PASS shale` (fmt, clippy -D warnings, tests, zero-dependency check all green).
- Tests: 31 (29 unit and property tests incl. crash at every write over 100 sequences x 30 ops, planted-fault fsck tests, T06 property tests; 2 existing leader tests untouched). Test run about 8 s.
- Journal overflow: if the in-use blocks of one commit exceed the journal capacity (min(journal blocks - 1, 509)), the operation returns `TooLarge` before anything is written. Direct writes of free blocks are not limited.
- Uncertain: no new `Error` variant; `TooLarge` reused with its doc extended. fsck returns `Corrupt` only for a bad superblock; other damage is reported. Repair frees orphans and unowned blocks only when the tree is trusted.

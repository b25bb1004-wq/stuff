# T91 silicon: probe (report)
API: `silicon::probe::{Probe, EcallRecord, ECALL_RING}`; `Machine::probe() -> Probe` (by value), `Machine::probe_reset()`. Probe: `exceptions[32]` and `interrupts[32]` by cause code, `uart_in`/`uart_out` (host-fed RX bytes / guest THR bytes), `block_reads`/`block_writes` (accepted commands 1 and 2), `ecall_total()`, `ecalls()` (last 64 `a7`+`instret`, oldest first).
Counted only on trap and device paths: `tick_with` trap and interrupt arms (trap.rs), UART `push_input` and THR write, block `execute` after the command check. Nothing added to the instruction path. `Cpu` holds a private `HartCounts` excluded from its `PartialEq`, so Cpu equality is unchanged.
Tests: 3 unit (src/probe.rs), 6 integration (tests/probe.rs: ecall and exception causes, ECALL ring a7/instret, timer interrupt, UART counters, block counters, reset). Full silicon suite passes, incl. riscv_tests.rs (6) and riscv_leader.rs (6); I did not count the "110 riscv-tests" separately.
Speed, release `examples/bench`, cache-on MIPS, 4 runs each. Before: bench 18.6 to 34.5 (median 25.2), loop 27.2 to 51.4 (median 33.1). After: bench 35.5 to 36.2 (median 35.7), loop 46.6 to 50.8 (median 49.1).
The 3 percent target is NOT verified: run-to-run spread is about 2x and the after-set is faster than the before-set, which points to machine load, not the change. No A/B on identical load was possible (no git allowed).
